# Function Logic Map: `_verified_go_entries` (Python, a122 task 7.5.34 — 새 함수)

`ast.after-7.5.34.json` — 분기 **18** · raise 5 · 반환 1.

## 답하는 질문

커밋마다 `*.go` 경로 → (모드, oid) 를 **검증한** 커밋과 트리에서만 읽는다. git 은 뿌리 트리 · 커밋은 파싱할 때 해시를
보지만 **하위 트리는 해시 없이 읽는다** — 하위 트리를 빈 트리로 위조하면 `ls-tree -r` 에서도 그 아래 파일이 조용히
사라진다(2.43 실측, 7.5.34 작업 중). 그래서 트리를 git 에게 걷게 하지 않는다.

## 믿는 것

`hints` 와 `ls-tree` 의 대답은 믿지 않는다 — 물을 목록일 뿐이다. 커밋 oid 는 `rev-parse <base>^{commit}` 의 답을 믿는다
(base 는 `base-commit.txt` 의 sha 이고, 그 이름이 무엇을 가리키는지가 곧 base 의 정의다).

## task 7.5.35 — 검증한 트리도 git 이 쓰는 모양이어야 한다 (2026-09-25)

`ast.before-7.5.35.json`(분기 18 · raise 5) → `ast.after-7.5.35.json`(분기 **26** · raise **6**) · 반환 1 그대로. difflib 정렬:
편집 전 B1–B16 은 그대로, **새 B17–B24** 가 트리 항목 읽기와 걷기 사이에 들고, 편집 전 B17 · B18 은 **B25 · B26** 이
된다(위 표의 B17 · B18 은 편집 전 번호다).

| 분기 | 뜻 |
|---|---|
| B17 | 정렬 열쇠 — 하위 트리는 이름 뒤에 `/` 를 붙인다(git 의 `base_name_compare`). 그래서 `a.go` 가 디렉터리 `a` 앞이다. gitlink 는 파일처럼 견준다(`b` 가 `b-.go` 앞) |
| B18 | 모드가 기본 `git fsck` 가 받는 여섯(`40000` · `100644` · `100664` · `100755` · `120000` · `160000`)이 아니다 → 거절. `100664` 는 초기 git 이 쓴 모드라 받는다(첫 판은 거절 — 적대 재리뷰 P2-1). `040000` 을 git 은 디렉터리로 읽지만 편집 전 걷기는 건너뛰어 그 아래가 판정에서 사라졌다(적대 재리뷰 P0-1) |
| B19 · B20 | 이름이 비었거나 `/` 가 들었거나 `.` · `..` → 거절. `/` 든 이름은 걷기가 하위 트리의 같은 경로와 하나로 모으는데 git 은 둘 다 낸다(`ls-tree -r` · diff — P1-2; 7.5.35 정정: 첫 판은 "git 은 하위 트리의 것만 본다" 라 적었다) |
| B21 | 같은 이름이 이미 나왔다 → 거절. 파일과 트리가 한 이름을 가지면 열쇠(`sub` · `sub/`)는 달라 순서 검사를 지나므로 이 갈래만 잡는다. 같은 이름은 **붙어 있지 않을 수 있어**(`x.go` · `x.go-` · 트리 `x.go` — 열쇠가 엄격히 오른다) 옆 항목이 아니라 본 이름 전부와 견준다(적대 재리뷰 P2-2 — 옆만 보는 검사는 편집 전의 조용한 삭제 손실을 다시 연다) |
| B22 | 열쇠가 앞의 것보다 크지 않다 → 거절(순서 어긋남). 같은 이름이면 B21 이 먼저 잡으므로 `<=` 와 `<` 는 같은 행동이다(변이에 안 넣었다) |
| B23 | 사유가 있으면 이름 대고 멈춘다(`NOT_CANONICAL` — 트리 · 자리 · 커밋 · 사유) |
| B24 | 문장의 자리: 뿌리면 `/` |
| B25 · B26 | (편집 전 B17 · B18) 하위 트리는 걷고, `.go` 로 끝나는 트리 아닌 항목만 모은다 |

빈 이름은 git 의 `ls-tree` 가 먼저 죽는다(`empty filename in tree entry` — 그것도 이름 댄 거절). 목록을 비워도 뿌리 트리는
`rev-parse` 힌트로 물으므로 걷기가 그 항목을 보고 B19 · B20 이 거절한다 — 시험은 두 층을 따로 잰다.
