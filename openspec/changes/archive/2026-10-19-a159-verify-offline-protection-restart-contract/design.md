## Context

기준 HEAD `1dbff7ced3653e3e9c1aaa892d18d76b1a50d511`. a155 완료 후 별도 오프라인 시험 분리를 사용자가 승인했다. a156과 a157은 이 change의 수정 대상이 아니다. Manager가 명세·최종 검증, Terra가 단일 구현 writer, 별도 reviewer가 독립/gstack 검토를 맡는다.

## Goals / Non-Goals

**Goals:** 동일한 임시 원장에 형성된 체결·캠페인·보호 상태가 재시작과 중복 입력 이후에도 보존되고, 실제 차단 사유에 의한 신규 진입 거절과 상태에 맞는 기존 청산 처리가 함께 성립하는지 검증한다.

**Non-Goals:** 생산 코드, 공개 테스트용 API, 새 전략·수량 산식·시장가 지원·마감 정책, 의존성, 스키마, 운영 설정, 실측·실주문, 기존 증거 수정. 시험 성공은 a156 완료나 정책 승급 근거가 아니다.

## Decisions

### 재사용과 증거

research-first 조사와 AST는 구현 전에 생성한 `analysis/research-first.md`, `analysis/code-context/`로 보존한다. 후보는 기존 confirmed dispatch/RecordFill 시험, campaign 재생·차단 시험, a150 보호 및 exitloop 시험이다. 현재 소스의 AST와 해시로 사용 경로를 결속하며 그래프 누락은 직접 소스와 대조한다. 신규 의존성이나 외부 서비스는 필요 없다. 기존 저장소 라이선스·의존성 조건을 그대로 유지한다.

새 `_test.go` 파일 안에서 기존 테스트 도구를 재사용한다. 동등한 복합 시험이 있으면 재사용하고 중복 구현하지 않는다. 서로 무관한 단위 시험을 실행한 것을 하나의 복합 흐름 검증으로 표현하지 않는다. 핵심 흐름은 같은 임시 DB의 동일한 체결·캠페인·포지션 계보를 유지해야 한다. 생산 동작 변경이 필요하면 시험 범위 밖으로 판단하고 Manager에게 보고한다.

### 고정할 시험 상태와 기대값

1. 가짜 브로커의 정상 승인된 매수 수량 8과 같은 주문의 누적 체결 3을 기존 `RecordFill` 및 생산 적용 hook을 통해 반영한다. 기존 승인 fixture의 수량 8을 재사용하여 authority 설정을 복제하지 않는다. 직접 position 행을 넣고 실제 체결 반영으로 표현하지 않는다. projected position=3, cumulative filled=3, remaining=5와 계좌/종목/캠페인/세대·기존 보호 snapshot을 확인한다.
2. 기존 공개 보호 대사 경로로 명시적 진입 차단을 발생시킨다. 실제 source/AST가 정한 상태·이벤트 수·차단 이유를 검증한다. 미체결 BUY의 존재 자체를 새로운 차단 이유로 정의하지 않는다.
3. DB를 닫고 새 Journal로 재개방한다. 동일 체결과 동일 보호 대사 요청을 재생해 수량·보호 기준·세대·캠페인 버전·중복 방지 이벤트가 불필요하게 증가하지 않음을 확인한다.
4. 최신 campaign version, 유효한 다음 sequence, 새로운 command key로 다음 leg를 요청하고 정확한 `ErrExposureBlocked`를 확인한다. 버전 충돌·잘못된 sequence·과거 명령 재생 결과를 차단 성공으로 오인하지 않는다. 새 leg/command/주문 또는 노출 증가가 없어야 한다.
5. 같은 재개방된 원장을 사용하는 exit 관찰을 수행한다. 실제 미종결 BUY 잔량을 가짜 조회에서 숨기지 않고, 이 단계의 가짜 cancel은 명시적으로 실패/불확실 상태를 반환하도록 고정한다. 이 구간에서는 보호 판단은 계속되고 새 매도 제출은 0이며, 기존 지연 한계 경과 시 알림 증거를 확인한다. 시간은 가짜 시계로 전진한다. CONFIRMED working order와 gateway unsettled attempt는 구별한다. 정상 확정 cancel을 받은 BUY까지 항상 terminal fill을 기다린다는 새 운영 계약을 도입하지 않는다.
6. 이 시험의 성공 단계에서는 명시적 terminal 매수 증거를 기존 반영 경로로 적용한 뒤 새로운 관찰을 수행한다. 이는 충분히 정리된 fixture 조건이며 모든 BUY 취소에 대한 새 필수 조건이 아니다. 기존 보호·신선도·floor 등 모든 guard를 충족하는 입력에서 확인된 sellable 이하의 가짜 청산 제출을 확인한다. 초기 floor 처리로 관찰이 한 주기 보류되는 기존 계약은 명시적 단계로 구분한다. 이미 SELL이 pending이면 신규 제출 0과 주문 보존을 기대한다. 중복 관찰로 중복 주문이 생겨서는 안 된다. 404·조회 부재만으로 terminal을 만들지 않는다.

보호 판단·알림·제출은 각각 별도 assertion으로 확인한다. production 상수나 결과를 읽어 기대값을 자기복제하지 않는다. 가짜 sellable, 가격, 시각, deadline은 기존 계약을 만족하도록 fixture에 명시하고 그 입력과 기대값을 검토 기록에 남긴다. KR fixture를 사용하며 US·실브로커 동작 검증으로 일반화하지 않는다.

### 대조군과 실패 탐지

같은 유효 입력 구조의 차단 없는 독립 캠페인에서 다음 leg가 허용되는 양성 대조군을 둔다. 다른 계좌/종목/세대의 차단이 적용 범위 밖 캠페인을 오염시키지 않는지 확인한다. 비손절 가격에서는 제출 0을 확인한다. 단순 fake 호출 카운트만으로 상태 보존을 주장하지 않는다.

양성 대조군도 첫 leg를 실제로 준비한 후 같은 유효 next sequence·최신 version·새 key를 사용한다. 정확한 차단 오류만으로 sequence 유효성이 증명되지는 않는다. pending SELL 대조는 같은 proposal과 보호 조건의 반복 관찰을 대상으로 하며, 다른 조건에서 기존 CancelPendingFirst 경로가 수행하는 취소·대체 청산을 금지하는 새 정책으로 일반화하지 않는다.

disposable copy 또는 Go overlay에서 진입 차단 검사를 무력화한 변이와 체결 중복 방지 또는 청산 중복 방지를 무력화한 독립 변이를 실행한다. 실제 behavioral assertion 실패를 요구하며 컴파일 실패나 테스트 기대값 자체를 깨뜨린 것을 RED로 세지 않는다. 변이가 효과 없으면 범위 안에서 더 적절한 seam을 선택하고 근거를 남긴다. 본 작업 트리의 생산 코드는 변경하지 않는다.

### 필수 규칙 적용

ai-memory: upstream 이름의 프로젝트 조회는 실패했고 전역 조회는 빈 결과였다. 기억 성공을 주장하지 않으며 현재 소스·OpenSpec을 기준으로 한다. durable memory는 쓰지 않는다.
grill-me: 별도 완료 단위 분리를 사용자가 승인했다. 정책 선택·실거래 승인은 요청하지 않는다. 남은 시험 상태·호출 경로는 소스로 결정한다.
impeccable: N/A — 내부 회귀 테스트·문서 전용, UI 변경 없음.
기존 고위험 함수 편집은 없으므로 편집용 FLM/BTM은 N/A이다. 다만 분기 근거는 사전 AST와 경로 대조로 보존하고, 게이트가 추가 증거를 요구하면 명시적으로 보완한다.

## Risks / Trade-offs

- 인위적 fixture가 보호 guard를 건너뜀 → 실제 RecordFill·원장 조회·owner 계보와 상태별 부정/양성 대조군 검증.
- 테스트 수만 증가하고 연결 실패를 못 찾음 → 같은 DB의 복합 흐름과 의미 있는 변이 실패 요구.
- 기존 계약을 새 정책처럼 변경 → 생산 변경 금지, 미종결/terminal/pending SELL 기대값 분리.
- 합성 증거의 과대 해석 → 오프라인 KR 회귀 증거로 한정, a156 실증 조건 유지.

## Migration Plan

마이그레이션·배포·재시작 없음. 새 테스트와 문서만 제거하면 되돌릴 수 있다. 리뷰·동결·최종 sync/check·전체 gate 실제 통과 후 정식 spec sync/archive와 PM 경로 검증, 범위 한정 commit 및 정상 push를 수행한다. 원격 변경이 있으면 보존하고 충돌을 검토한다.
