# operator-console Specification (delta)

## ADDED Requirements

### Requirement: 콘솔이 교착된 조건주문 체인을 다시 열 수 있다

검증 화면의 `[재측정]`은 **콘솔만으로 측정을 재개할 수 있어야 한다**(SHALL). 측정 대상이
사라져 모든 후속 단계가 skipped로 굳은 체인이 콘솔에서 되살아날 수 없어서는 안 된다
(SHALL NOT) — 그 상태에서 CLI 플래그가 유일한 탈출구여서는 안 된다(SHALL NOT).

무엇을 재측정할지는 **디스크의 증거**가 정한다(SHALL). 재측정 대상 목록이 요청 폼으로
전달되어서는 안 된다(SHALL NOT) — 이 소켓에 닿는 무엇이든 단계를 지명할 수 있게 되면
승인 모델이 아니라 요청이 범위를 정하게 된다.

재측정 표가 "이 실행이 건드릴 행"으로 표시하는 집합은 실제 재측정 집합과 **동일해야
한다**(SHALL). 표가 판정만 보고 판단해 집합과 다른 행을 보여서는 안 된다(SHALL NOT).

근거: 2026-07-28 이후 KR 조건주문 체인은 콘솔에서 `[이어하기]`도 `[재측정]`도 아무것도
바꾸지 못하는 상태였다. 사용자는 콘솔에서 검증을 운전하며, 이 저장소는 콘솔 막다른 길로
이미 장중 창 세 개를 지불했다(measurements.md M11·M18).

#### Scenario: 대상이 사라진 체인이 콘솔에서 재개된다

- **WHEN** 조건주문이 사라져 존속·정정·취소가 skipped로 굳은 기록에서 `[재측정]`을 누르면
- **THEN** 실행 계획에 조건주문 등록이 포함되고, 승인 뒤 체인이 다시 측정된다

#### Scenario: 재측정 표와 실제 대상이 일치한다

- **WHEN** 재측정 확인 화면이 대상 행을 나열하면
- **THEN** 그 목록은 실행이 실제로 걸을 재측정 집합과 같다

#### Scenario: 재측정 대상은 폼이 아니라 기록이 정한다

- **WHEN** 재측정 요청이 단계 이름을 담아 도착하면
- **THEN** 그 이름은 무시되고 대상은 증거 기록에서 다시 계산된다
