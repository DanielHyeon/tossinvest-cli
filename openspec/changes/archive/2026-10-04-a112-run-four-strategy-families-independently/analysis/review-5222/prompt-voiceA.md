# 목소리 A — 적대 공격: 범위 거절 경계 · 굶김 · CAS 창 · 위조

공통 브리프를 먼저 읽는다. 공격 지점 ①②가 본령이다.

필수 판정:
1. **J4 경계 — 오분류 양방향.** (a) 범위 거절이 **아닌** 오류(원장 · Gateway · 중앙 무결성 · identity 불일치 · 캠페인 CAS · 위험 범위 불일치 · 통화 미지)가
   `*strategyScopeRefusal` 로 분류되어 전달 몸통이 건너뛰고 **같은 주기의 다음 범위를 내는** 경로가 있는가 — `errors.As` 의 체인(`%w` · `errors.Join` · 감싼 타입)을 따라가며
   다른 오류가 그 타입을 품게 되는 자리를 찾아라. (b) 반대로 범위 거절이어야 할 것이 타입을 잃고 주기를 멈추는 자리(굶김). census 시험이 실제로 「만드는 자리 둘」을
   강제하는지 — census 를 통과하면서 새 생산자를 만드는 철자(별칭 · 형 변환 · 다른 패키지 · 함수 값)를 사본에서 시도하라.
2. **파도 순차 발급의 CAS 창.** 같은 파도 둘째 범위가 `BUCKET_USAGE_STALE` 로 거절되는 것을 시험이 잰다. 이 보호가 **항상** 서는가 — 공유하지 않는 버킷 조합, 섹터가 다른
   두 종목, 첫 레그가 거절된 뒤 둘째, 둘째가 먼저 오는 순서, held 가 0 인 경우. 공유 bucket 이중 소비가 journal `checkLimits`/`refuseStaleBucketUsage` 를 우회하는 모양이
   있는가. 두-레그 시험(`TestTheSecondLegOfOneCycleCountsTheFirstLegsHeldReservation`)이 held 계상을 **직접** 재는가, 아니면 다른 이유(예: 계좌 권한 · 다른 상한)로 거절돼도
   통과하는가 — 사본에서 그 거절 원인을 바꿔 보라.
3. **위조 · 틀린 범위 권한.** 범위 A 의 위험 또는 계좌 권한으로 범위 B 가 발급되는 경로(키 정규화 차이 · 같은 종목 다른 세대 · 시장 칸 폴백 · `strategyRiskMarketFromScopes`
   의 첫 범위 칸을 읽는 다른 소비자). worker 승격의 「하나라도 통과」가 주문 경로의 범위 검사를 대체해 버리는 곳이 있는가.
4. 토글 OFF = upstream: 활성화 없는 시장에서 새로 **통과**하는 입력(P0) · 새로 거절하는 정상 입력을 찾아라.
