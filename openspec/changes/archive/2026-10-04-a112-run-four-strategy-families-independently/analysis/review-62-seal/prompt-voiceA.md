# 목소리 A — 적대 위조 공격(다섯 축 바깥)

공통 브리프를 먼저 읽는다. 로트가 시험한 위조 축 다섯(같은 범위 패자 · 게이트된 레인 · 미선택 범위 · 타 시장 · 같은 계보 조건 재작성)과 기제 둘(범위 중복 · 개수 관문 앞 선택)
**바깥**의 위조 축을 찾는 것이 본령이다. 봉인이 **의미**(조립이 중재하지 않은 봉인 제안은 1차 레그가 발급되지 않는다)를 재는지를 부숴라.

필수 판정:
1. **새 위조 축.** 예: 같은 범위 · 같은 identity 인데 다른 **포지션 세대**(세대가 바뀐 재진입), 계좌 표기 · 종목 대소문자로 정규화 전후가 갈리는 것, `accepted.market` 과
   `accepted.result.Lineage.Market` 불일치의 다른 조합, 조립의 권한 쌍 자체가 **다른 파도**의 것인 경우(새로 고침 사이 경합 — loader 의 pair 와 dispatch 주기의 pair 가 같은
   파도인지), 위험 · 계좌 권한 쌍과 제안 쌍이 서로 다른 범위를 가리키는 경우, `validateStrategyFirstLegResult` 를 우회해 accepted 를 만드는 길. 각 축을 사본에서 **실행**으로
   시험하고(1차 레그가 발급되는지 — `collectStrategyFirstLegAuthority` 가 err=nil 을 돌려주는지) 결과를 적어라.
2. **범위 선택 → identity 대조 순서를 뚫는 조합.** 선택이 accepted 에서 읽는 값(계보의 네 축)을 위조해 **다른** 합법 항목을 고르게 하고, 그 항목의 identity 와 accepted 의
   identity 가 같아지는 경우가 있는가(= 대조가 공허해지는 조합). `NewOwnerKey` 정규화와 `Lineage.Identity` 해시의 입력이 어긋나는 자리.
3. **A-lite 와 봉인 사이 틈.** A-lite 가 닫는 것과 봉인이 닫는 것 사이에 둘 다 못 보는 모양이 있는가. A-lite 가 **생산**(활성화 없는 시장)을 바꾸는가.
4. 토글 OFF = upstream: 활성화 없는 시장의 1차 레그 판정이 편집 전과 같은가(새로 거절하는 정상 입력은? — 0 이어야 하지만 「더 엄격」은 허용. 새로 **통과**하는 입력은 P0).
