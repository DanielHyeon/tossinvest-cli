## 응답
1. **BLOCKER — Missing execution fields can become a false zero-fill terminal.** D3 reuses `parseSnapshot` and accepts quantity equality (`design.md:65–74`). But absent `execution` leaves filled quantity zero; absent/null `filledQuantity` also becomes zero (`internal/filldetect/payload.go:81–90,178–184`). `CANCELED` with positive quantity and zero fills derives clean `CANCELLED` (`internal/brokerstate/derive.go:441–453`). Thus a stale single read reporting zero plus a CLOSED row omitting execution can close a partially filled order and release its reservation (`internal/journal/fills.go:512–519`). **Change:** validate field presence separately from numeric value before terminal promotion; require explicit execution evidence or a documented, verified null-semantics contract. Add missing/null execution tests.

2. **BLOCKER — The claimed “complete CLOSED walk” can actually be truncated.** D2 relies on `ScanOrders` for completeness (`design.md:56–57`), but it returns success when `HasNext=true` and `NextCursor=""` (`internal/execgw/indoubt.go:754–756`). A terminal candidate on that page can be accepted without seeing a conflicting later row. **Change:** reject contradictory pagination metadata; test `hasNext=true` with empty/whitespace cursor before asserting uniqueness.

3. **MAJOR — Duplicate handling does not implement “exactly one row.”** The requirement demands exactly one matching row (`specs/fill-detection/spec.md:7–8`), while D3 rejects only different canonical keys and permits duplicate byte-identical rows (`design.md:67–68`). It leaves same-key, different-status/quantity rows unspecified. Canonical keys contain no status, quantity, or observation version (`internal/filldetect/detect.go:460–466`). **Change:** reject every repeated matching ID, or explicitly define full-payload deduplication and reject all conflicting observations. Test same-scope `CANCELED` versus `PARTIAL_FILLED`, including reversed page order.

4. **BLOCKER — “Equal quantities means no fill event” is false; CLOSED can supply the price of a new fill.** Q5 asserts `delta>0` is false because the two responses agree (`design.md:229–233`). Actual delta compares incoming quantity against the **previous journal snapshot**, not the single read (`internal/journal/fills.go:379–382,412–415`). Example: journal=0, single=`PARTIAL_FILLED`/4, CLOSED=`CANCELED`/4. D3 accepts and replaces price, amount, and timestamp (`design.md:73–74`); `RecordFill` inserts delta=4 using the CLOSED price (`internal/journal/fills.go:464–475`). **Change:** preserve single-read execution fields when applying terminal evidence, or explicitly authorize and validate CLOSED execution authority. Add tests where both responses agree but exceed the durable baseline, and where CLOSED execution metadata is absent or conflicting.

5. **BLOCKER — Additional reads can delay protective liquidation despite separate loops.** All CLOSED scans run inside `collect`, before **any** snapshot is applied (`design.md:160`; `internal/filldetect/detect.go:293–317`). One slow unrelated lookup therefore delays already-read protective fills and cancellations. The exit loop explicitly waits for cancellation terminal evidence (`internal/app/engine/exitloop.go:1667–1678`), and pending proposals resolve through the fill hook (`internal/journal/apply_hook.go:1009–1012`). Even with accountbudget enabled, Critical cannot preempt a wire owner; ownership includes response-body consumption (`internal/accountbudget/budget_linux.go:549–584`; `transport_linux.go:177–188`). The default HTTP timeout is 15 seconds (`internal/official/client.go:22,137`). **Change:** specify a bounded enrichment deadline and cycle-wide work limit; prevent unrelated enrichment from delaying authoritative fill application. Verify protective-order latency under slow CLOSED responses.

6. **MAJOR — Successful-cycle freshness would conceal unresolved required evidence.** The new spec expressly stamps freshness after CLOSED failure (`specs/fill-detection/spec.md:37–39`), contradicting the existing incomplete-picture contract (`internal/filldetect/detect.go:273–276,622–629`). `pollLocked` also clears outage state, while freshness is stamped at completion rather than the OPEN observation time (`detect.go:346–348`; `internal/execgw/retry.go:545–554`). Entry admission checks those stamps (`retry.go:642–658`). “Reconcile will block” is not an equivalent guarantee: missing-order blocks initially have symbol scope (`internal/reconcile/mismatch.go:1418–1427`). **Change:** separate successful snapshot application from completeness/freshness. Preserve useful writes while withholding the relevant freshness credit or explicitly tracking unresolved-order admission state.

7. **MAJOR — Rate accounting understates requests and has no aggregate bound.** D10 quotes approximately 0.033 requests/second per unresolved order (`design.md:143`), but each lookup can issue three page requests (`internal/execgw/indoubt.go:743–752`): up to **0.1 requests/second per order**, excluding single reads. Multiple orders sharing a symbol/date window repeat the same scan; restart resets every throttle simultaneously (`design.md:96–99`). The poll mutex serializes work (`internal/filldetect/detect.go:277–280`), but supplies neither a global budget nor restart protection. **Change:** account for pages, bound total CLOSED work per cycle, and reuse identical completed queries within a cycle. Specify lookup timing from attempt completion and restart behavior; test many unresolved orders and repeated restarts.

8. **MAJOR — The stated reconcile safety net does not cover all false-terminal outcomes.** The design admits stale-zero and same-scope ID-reuse cases, then claims holdings reconciliation blocks them (`design.md:199–202`). A still-live unfilled order creates no holdings mismatch. A positive holding without a local position is classified as external (`internal/reconcile/compare.go:410–417`), and external records do not make `BlocksEntry` true (`compare.go:306–313`). Terminal promotion meanwhile removes ordinary tracking and releases reservations (`internal/journal/fills.go:1604,512–519`). **Change:** remove the unconditional safety claim. Establish broker identity/version and terminal-evidence assumptions explicitly; retain post-terminal verification or require operator resolution where those assumptions cannot be established.

9. **MAJOR — Normal amend timing can still create an immediate latch, despite the 30-second reporting story.** D1 includes UNKNOWN as a proposed option, while unsuccessful enrichment retains the original snapshot (`design.md:45–48,78–79`). A single `PENDING`/`PENDING_REPLACE` with known successor is UNKNOWN (`internal/brokerstate/derive.go:392–394,520–522`). If CLOSED is delayed, the existing path immediately records refusal and blocks the gate (`internal/journal/fills.go:385–409`; `internal/filldetect/detect.go:324–327,682`). The new 30-second notification delay does not delay that existing action. **Change:** distinguish unresolved-but-consistent reads from contradictory derivations in the contract; specify recovery for the latter. Add an amend sequence covering delayed lineage, delayed CLOSED visibility, eventual terminal evidence, and resulting gate state.

10. **MAJOR — Recovery promises remain false for supported legacy rows.** The design acknowledges the legacy exception but still states local open orders disappear and resolution becomes executable (`design.md:213–228`). An unscoped legacy row survives the scoped-row exclusion (`internal/journal/fills.go:888–900`), cannot be updated by the exact-scope mirror (`fills.go:795–799`), and can remain tracked through the legacy-owner branch (`fills.go:1604–1614`). `LocalStateFromJournal` consumes that result (`internal/reconcile/compare.go:201–212`), so `reconcile-resolve` still refuses the remaining difference (`cmd/tossctl/engine_reconcile.go:198–199`). **Change:** make recovery conditional and add a legacy fixture plus an explicit migration/operator-repair prerequisite. Missing-order-only symbol blocks also receive no convergence credit (`internal/reconcile/converge.go:142–145`) and therefore do not self-release (`internal/reconcile/mismatch.go:662–668`); operator resolution is the actual release path (`mismatch.go:1323–1356`).

11. **MINOR — Existing tests cannot substantiate “behavior unchanged.”** The old pager returns pages solely by cursor despite recording status (`internal/filldetect/detect_test.go:55–66`). Keeping it unchanged and adding a separate fake (`design.md:157–159`) leaves old tests unable to reject accidental CLOSED calls. The existing terminal-removal test checks fills/tracking, not CLOSED-query absence (`internal/filldetect/ledger_test.go:296–317`). **Change:** make old fakes reject unexpected query statuses, or add explicit query-sequence assertions. This is a coverage gap, not a demonstrated failing test.

12. **NIT — One AST citation has the wrong branch kind.** `design.md:191` cites `Derive B45(if@475)`. It is a switch **case**, both in source (`internal/brokerstate/derive.go:475`) and the supplied AST (`analysis/cited-ast/internal-brokerstate--derive.ast.json:369–373`). **Change:** use `B45(case@475)`.

**Verdict:** Do not implement this design unchanged. Terminal evidence validation, execution-field authority, freshness semantics, and protective-path latency need correction first. The ±1-day window matches the current market-local calendar-date model (`internal/clock/market.go:154–163`); it does not establish observation freshness or same-day identity uniqueness.
