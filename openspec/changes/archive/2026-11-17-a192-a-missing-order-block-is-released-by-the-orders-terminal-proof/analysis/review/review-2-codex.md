## 응답
References `design`, `delta`, and `tasks` mean files under the reviewed change directory.

1. **BLOCKER — M11(ii) repeats the timestamp-versus-commit mistake.**  
   Refused positive-delta projections **do** retain their `fill_events` row: insertion precedes hooks (`internal/journal/fills.go:464–472,551–556`), and an already-active reconcile row makes the projection refusal return nil (`internal/journal/position_projection.go:101–103,401–405`). However, `committed_at` originates before `BeginTx` and is adjusted only against snapshot/ownership timestamps (`fills.go:333–339,373`). Counterexample: fill captures T1; missing-order block commits with `entered_at=T2`; fill subsequently acquires the transaction and commits its refusal carrying T1. C12’s `committed_at > entered_at` misses it. Thus `design:256–258,450` cannot claim this closes #1.  
   **Change:** Use a transactionally captured event-ID watermark or durable producer disqualification, rather than wall-clock ordering. Scoped events contain account/symbol; legacy attribution requires the existing `allFillEventsCTE` join through `legacy_fill_event_bindings` (`fills.go:1046–1057`). Specify that coverage and fail-closed handling of unresolved attribution. Test the pre-timestamp/block-commit/fill-commit interleaving.

2. **MAJOR — D5’s transactional verdict lacks an executable read and callback contract; #3/#4 are only partially closed.**  
   `design:231,239` names existing public lineage/fill readers, while `design:283–288` requires their results inside the release transaction. Those readers use `j.db`, not its transaction (`internal/journal/fills.go:1010–1011`; `internal/journal/lineage.go:419–420`). With one database connection (`internal/journal/journal.go:174`), calling them while holding the transaction waits on that same connection. The lineage reader can additionally call `EnterReconcile` on conflict (`lineage.go:334,442–454`).  
   A callback **need not** create an import cycle or lock inversion: journal-owned argument/result types and a pure closure suffice. But `Observe` already holds `t.mu` through persistence (`internal/reconcile/mismatch.go:623,767,831`); callback re-entry into locking Tracker methods would deadlock. The transaction also cannot reconstruct `Diff` account/as-of/disputes/external orders or `bindingUnwritten` from journal rows (`design:221–222`).  
   **Change:** Specify transaction-bound readers, explicit lineage-error propagation, and a pure callback capturing immutable comparison/Tracker inputs under the existing lock. Prohibit public Journal calls and Tracker re-entry inside that callback. Distinguish the frozen comparison from freshly read journal proof.

3. **MAJOR — `INSERT OR IGNORE` can clear `bindingUnwritten` without preserving the observed identity.**  
   D2 clears memory after successful writes (`design:208–213`), but its primary key omits `account_ref` and `original_order_id` (`design:194–199`). An existing legitimate binding and a later foreign-account binding with identical market/day/side/order ID collide. `INSERT OR IGNORE` succeeds while discarding the foreign identity; memory clears, and C4 subsequently sees only the legitimate row. This defeats the intended combination of fixes #2/#5. Foreign-account missing orders really can reach the tracker’s symbol block (`internal/reconcile/mismatch.go:1418–1429`).  
   **Change:** Clear memory only after committed, lossless representation of every accumulated identity. Either distinguish complete identities or durably disqualify conflicting payloads. Specify that skipped rows, partial writes, ignored conflicts and rolled-back transactions do not count as successful persistence. Add collision and failed missing-order-attachment tests.

4. **MAJOR — M12(iii) is sound for an unchanged proof set, but arming has no invalidation contract.**  
   Production `Run` executes cycles serially (`internal/app/engine/reconcileloop.go:397–403`); each subsequent `RunOnce` reads local state after collection (`:417–428`). Therefore, after arming on committed terminal evidence, the next cycle’s local read sees that evidence. Restart dropping the arm conservatively delays release.  
   However, `design:263–266` stores only comparison as-of, while D2 allows additional bindings (`design:206–211`). Counterexample: arm for A; later bind missing order B; B commits terminal during another comparison after its local read; that comparison passes using A’s old arm although B was still matched to broker OPEN. M11 does not catch a zero-delta cancellation (`internal/journal/fills.go:464`).  
   **Change:** Bind arming to the exact reconcile row and proof/binding generation. Invalidate it when bindings or relevant proof change; require a fresh passing observation before release. Document the serial, fresh-comparison requirement and test this sequence, row replacement, and restart.

5. **MAJOR — Revised recommendations still contradict the normative delta and completion checklist.**  
   `delta:31–38` requires the same verdict after restart; `design:214–215,296–297` loses unwritten disqualification evidence, while recommended M12 intentionally loses arming (`design:265–266`). `delta:9–11` and tests at `design:384–386` still prescribe release on the first qualifying comparison. C12’s additional retention condition is absent from that release scenario. Meanwhile `tasks:3–4,16` requires only M1–M10, omitting the expressly blocking M11/M12 decisions.  
   **Change:** Present explicit conditional delta/test amendments for each Manager option: durable-proof consistency versus process-local arming, re-arming after restart, M9’s acknowledged exception, and C12 retention. Update the checklist to M1–M13. #7’s enabled-path coverage is added at `design:401–405`, but remains a plan and needs the counterexamples above.
