## ADDED Requirements

### Requirement: 검증 단계 목록은 구조화된다

검증 화면의 단계 목록은 단계별 항목(제목·상태 변경 여부 표시·요약)으로 렌더해야 하며(SHALL), 각 항목의 전체 내용은 접힌 블록 안에 남아 `tossctl verify run --list` 와 같은 내용을 유지한다(SHALL). 검증 시작·승인·중단 폼과 그 CSRF·확인 문자열 절차는 바뀌지 않는다(SHALL NOT).

#### Scenario: 단계 목록 읽기
- **WHEN** 검증 화면을 열면
- **THEN** 단계 제목과 상태 변경 여부를 스크롤 한 화면 안에서 훑을 수 있고 각 단계를 펼치면 종전 전체 내용이 보인다

### Requirement: 개요의 같은 설명은 한 번이다

개요 화면의 요약 영역은 「운영 개요 가시성」의 여섯 사실과 시장별 분리·미측정 사유·상세 링크를 유지하면서 1280px 폭에서 세로 스크롤 없이 읽혀야 한다(SHALL). 구조적 미측정처럼 여러 칸에 걸친 같은 설명은 1회만 렌더한다(SHALL). 검증 기록 파일 경로 같은 개발자 식별자는 접힌 기술 정보에 둔다(SHALL). 기존 상세 섹션은 제거되지 않는다(SHALL).

#### Scenario: 세 축 구조적 미측정
- **WHEN** 오늘 소진분의 한 축만 산출 가능한 상태로 개요를 열면
- **THEN** 나머지 축이 구조적으로 미측정이라는 설명은 1회 나타나고 각 축의 칸은 사유 코드만 반복한다
