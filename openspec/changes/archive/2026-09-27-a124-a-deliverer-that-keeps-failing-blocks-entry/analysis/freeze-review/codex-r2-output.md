D7’s proposed executor path has **no demonstrated lock-order cycle**: `Block` releases `g.mu` before escalation, mode projection occurs after commit, and a nil announcer avoids Notifier reentry (`retry.go:526–533`; `operating_mode.go:468–479`). Remote publish also remains outside the executor’s critical section. These facts do **not** prove bounded exit delay.

Synchronous rearm adds another interleaving beyond D7’s table. A successful old-token settlement is safely rejected as `LeaseLost` after rearm (`outbox.go:334–340`; `alert_claim.go:357–364`). That protects persisted attempts; it does not reset D8’s ID-keyed memory or resolve storage errors that prevent classification.

The cancellation exclusion is sound **if it checks the executor’s lifetime context**: Run exits when that context is cancelled (`alertdelivery.go:124–134`). A transport timeout uses a child context (`internal/obs/ntfy.go:95–100`) and must still count as failure. Specify this distinction in T:2.10.

**D2 and D3 are adequately justified as policy choices**, with qualifications:

- **D2, limit 3:** matches the existing default and production wiring (`notifier.go:38–48`; `exitwiring.go:73–79`). Equal elapsed time applies only to the isolated single-row examples, not loaded operation.
- **D3, missing publisher counts:** directly follows existing intent (`exitwiring.go:62–70`) and a092’s explicit requirement (`a092…/specs/engine-safety/spec.md:76,108–110`). The acknowledged 4–6s example is likewise unloaded, not an operational maximum.

VERDICT: REJECT — acknowledgement/error fencing, successful-publish settlement failures, counter lifecycle, exit-delay evidence and timing bounds must be resolved before freeze.
