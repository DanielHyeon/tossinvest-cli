D1’s transactional `Attempts` read is implementable: read through **`tx`**, before commit, return the value only after successful commit, and return an error on read/commit failure. That preserves the existing CAS boundary. The failure-record NotFound latch-only parity claim is correct. The added read also affects delivered settlement and release, so their failure behavior deserves explicit regression coverage (`internal/journal/alert_claim.go:316–344,375–379`).

D2 and D3 are adequately justified **as policy choices**. Three reuses the existing retry budget (`internal/obs/notifier.go:40–48`); increasing it would delay blocking. Counting a missing publisher follows existing wiring intent and a092’s explicit requirement (`internal/app/engine/exitwiring.go:60–70`; a092 delta `:74–76`). The 4 s/34 s comparison applies to an isolated row with the stated exclusions; it is not general latency parity.

The delta and tasks now cover most intended behavior, but they also encode Q3’s unsafe evidence-discard rule. Fixing implementation alone would conflict with those SHALLs; revise the contract and add the missing schedules before freezing.
