## ADDED Requirements

### Requirement: 엔진의 침묵은 엔진 밖에서 판정된다

죽은 엔진 프로세스는 스스로 통지할 수 없으므로, 엔진의 생존 신호가 끊겼다는 판정과 그 알림은 엔진 프로세스 밖에서 이루어져야 한다 (SHALL).
「등급화된 알림」 요구의 heartbeat 문장이 말하는 수신 측 경보는 이 요구로 이행한다: ntfy 는 오지 않은 메시지를 판정하지 않으므로, 판정은 호스트의
감시 명령(`tossctl engine heartbeat-check`)이 하고 경보는 그 명령이 ntfy 로 보낸다 (SHALL).

엔진의 생존 신호는 엔진 활성 마커(저널 디렉터리의 `engine-run.json`, 갱신 1분)다. 감시 명령은 마커의 갱신 시각만으로 판정해야 하며 (SHALL),
엔진 · 저널 · 엔진 잠금을 요구하거나 열어서는 안 되며 브로커 API 를 불러서는 안 된다 (SHALL NOT). 판정은 다음과 같다 (SHALL):

- 마커가 기준(기본 3분)보다 오래되었으면 엔진은 끊김이다 — `engine.autostart` 와 무관하다.
- 마커가 없고 `engine.autostart` 가 ON 이면 엔진은 끊김이다.
- 마커가 없고 `engine.autostart` 가 OFF 이면 감시 대상이 아니다.
- 마커를 볼 수 없으면(부재 외의 오류) 부재로 단정하지 않고 실패로 끝내야 한다.
- 기준은 마커 갱신 주기(1분)보다 길어야 하며 그렇지 않으면 명령은 거절해야 한다.

끊김으로 바뀐 순간 critical 알림을 정확히 한 번, 끊김에서 벗어난 순간 복구 알림을 정확히 한 번 보내야 한다 (SHALL).
끊김에서 벗어나는 것은 재시작 복구를 마쳤다고 적은(`ready_at`) 신선한 마커이거나 감시 대상이 아니게 된 경우뿐이어야 하며 (SHALL),
복구를 마치지 않은 신선한 마커는 끊김을 유지해야 한다 (SHALL). 같은 끊김이 이어지는 동안
알림을 반복해서는 안 된다 (SHALL NOT). 상태의 이동은 전송이 성공한 뒤에만 기록해야 하며 (SHALL), 전송이 실패하면 다음 실행이 다시 보내야 한다 (SHALL).
읽을 수 없는 상태 기록은 알림을 억제하는 방향으로 읽혀서는 안 된다 (SHALL NOT).

감시 명령의 전송 수단은 엔진과 같은 알림 설정 해석 규칙으로 얻어야 하며 (SHALL), 「시스템 밖으로 나가는 알림에는 계좌 정보가 실리지 않는다」의
전송 경계를 지나야 한다 (SHALL). 알림이 꺼져 있거나 채널이 설정되지 않아 보낼 수 없으면 명령은 이유를 말하고 실패로 끝내야 하며 (SHALL),
성공으로 끝나서는 안 된다 (SHALL NOT). 설치 때 전달을 실측할 수 있도록 같은 전송 수단으로 시험 알림 한 건을 보내고
전달되지 않으면 실패로 끝나는 방법을 제공해야 한다 (SHALL).

생존 신호 파일 · 감시 상태 파일 · 감시 알림에는 계좌 칸이나 계좌 정보가 실려서는 안 된다 (SHALL NOT). 이 요구는 엔진 런타임 · 감독 루프 ·
마커의 갱신 주기 · stale 창(5분) · flock 배타를 바꾸지 않는다 (SHALL NOT).

#### Scenario: 엔진이 OOM 으로 죽고 콘솔은 건강하다
- **WHEN** 엔진 프로세스가 마커를 지우지 못하고 죽어 마커의 갱신 시각이 기준보다 오래되었고 감시 명령이 실행되면
- **THEN** critical 알림 한 건이 엔진 생존 신호 끊김을 알리고, 상태 기록이 끊김으로 바뀐다

#### Scenario: 같은 끊김의 다음 실행
- **WHEN** 끊김이 이미 알려진 상태에서 마커가 여전히 오래된 채 감시 명령이 다시 실행되면
- **THEN** 알림을 보내지 않는다

#### Scenario: 엔진이 다시 살아난다
- **WHEN** 끊김 상태에서 마커가 기준 안의 시각으로 갱신된 뒤 감시 명령이 실행되면
- **THEN** 복구 알림 한 건을 보내고 상태 기록이 끊김에서 벗어난다

#### Scenario: 재기동 루프의 짧은 마커는 복구가 아니다
- **WHEN** 끊김 상태에서 감시 명령이 재시작 복구를 마치지 않은(`ready_at` 없는) 신선한 마커를 보면
- **THEN** 복구 알림을 보내지 않고 끊김 상태를 유지한다

#### Scenario: 설치 때 전달을 실측한다
- **WHEN** 운영자가 시험 알림 방법으로 감시 명령을 실행하고 채널이 요청을 거절하면
- **THEN** 명령은 실패로 끝나고 감시 상태 기록을 바꾸지 않는다

#### Scenario: 돌아야 할 엔진이 없다
- **WHEN** `engine.autostart` 가 ON 인데 마커가 없고 감시 명령이 실행되면
- **THEN** critical 알림 한 건이 엔진 생존 신호 끊김을 알린다

#### Scenario: 정상 정지와 수동 운용
- **WHEN** `engine.autostart` 가 OFF 이고 마커가 없으며 이전 상태가 끊김이 아니면
- **THEN** 알림을 보내지 않고 성공으로 끝난다

#### Scenario: 전송이 실패한다
- **WHEN** 끊김 판정에서 알림 전송이 실패하면
- **THEN** 상태 기록은 바뀌지 않고 명령은 실패로 끝나며, 다음 실행이 같은 알림을 다시 보낸다

#### Scenario: 알림이 꺼져 있다
- **WHEN** 알림 설정이 꺼져 있거나 채널이 없는 상태에서 감시 명령이 실행되면
- **THEN** 명령은 보낼 수 없는 이유를 말하고 실패로 끝나며 상태 기록을 바꾸지 않는다

#### Scenario: 감시는 엔진을 요구하지 않는다
- **WHEN** 엔진이 실행 중이지 않고 저널 디렉터리에 엔진 잠금이 없는 상태에서 감시 명령이 실행되면
- **THEN** 명령은 저널과 엔진 잠금을 열지 않고 마커와 설정만으로 판정을 끝낸다

#### Scenario: 생존 신호에 계좌 칸이 생긴다
- **WHEN** 엔진 활성 마커 형식에 계좌 키 이름의 칸이 추가되면
- **THEN** 시험이 실패한다
