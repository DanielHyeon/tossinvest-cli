## Context

The 2026-10-17 offline diagnosis observed differing selection results and data availability across s3 market sessions. It cannot attribute those differences to a particular question or input. a128's `semantic-judgment-shadow` specification is still an active delta, not a main spec; preserve it and reconcile archive/sync order before merging either specification. This change does not claim a128 is complete. The offline leaf reads existing evidence independently; a128 completion is not an implementation predecessor, but its shared capability synchronization order remains a lifecycle dependency.

## Goals / Non-Goals

**Goals:** First evaluate input quality and existing choices from frozen data; independently specify an r2 comparison that remains blocked without compatible saved responses. Preserve provenance, prevent hindsight leakage and report uncertainty.

**Non-Goals:** Model or market API calls, collection, order/engine changes, operational deployment, threshold tuning, modifying r1/a128 raw evidence, or expanding the external response schema. This design authorizes neither implementation nor a new paid call.

## Decisions

1. **Snapshot and sidecar.** Freeze copies of the ledger and referenced states, record a manifest with hashes and as-of timestamp, validate links/digests and exclude secrets/account fields from derived output. Never rewrite source bytes. Derive only available facts in a separate quality sidecar: feed unavailable vs successfully read with an empty symbol-news list, article age as of observation, future-dated articles, market vs symbol headlines, intraday/daily, quote, market context and flows. Classify structurally unsupported separately from missing; unknown stays unknown. A feed marked present does not prove an article exists or that the feed is complete. Only input already present in the historical state snapshot is eligible; publication time alone does not prove availability at observation. Exclude later-collected material without as-of availability proof and classify unknown provenance as unknown.
2. **Analysis first.** Join labels by judgment ID, pair questions by identical state/cycle, and count each state once. Split lot, market and local session; compare existing selection with predeclared J1-only top K, J2-survivor uniform expectation and pool uniform expectation using the same K and cycle, with the existing tie rule. K is the actual r1 selection count, including when below ten; K=0 yields no selection or uniform-K return, so report and exclude that cycle from return comparisons. Exclude entire incomplete-label cycles from paired returns and report them separately. For return comparisons, average eligible candidates equally within each cycle, then average cycles equally, separately by market and session. For each quality stratum report state count, J2 exclusion rate, selection rate, 60-minute mean and missing-label count; explicitly distinguish any row-weighted stratum mean from the equally weighted cycle comparison and note repeated observations. Unknown is distinct and overlapping strata must not be summed. Stage 1 can complete independently of r2 availability. Report 60-minute price changes before costs, not account returns; repeated symbols and overlapping windows are dependent. Report session/cycle units and insufficient evidence as inconclusive, with no post-hoc threshold search.
3. **Paired J2 revision.** Retain r1 and its J1 question and scores; use r2 J2 responses only to replace J2 scores in the isolated replay. A new r2 lot must match the original model/version, frozen input state, observation identity and J1 wording, with only J2 wording different. Verify provenance before pairing; report any mismatch and exclude it rather than assume equivalence. A separately emitted J1 response is not substituted into this test. This is a fixed-J1 rule sensitivity analysis, not the performance of a joint r2 response; any effect of changed J2 wording on jointly emitted J1 is not measured. Require compatible paired responses for every eligible candidate in a cycle; otherwise exclude the entire cycle and report its reason and count. Predeclare K as the original r1 cycle selection count; if r2 has fewer than K survivors, defer that cycle from the equal-K paired comparison and separately report both actual selection counts, without filling or changing r1. Keep the existing binary `noul` true/false structure. Fix the r2 wording as follows:

   - **Question:** “Does this state show a clear, explicit adverse signal relevant to buying this stock now? Distinguish an unavailable news feed from a successfully read feed with no matching symbol headlines. Do not treat missing information by itself as an adverse signal, and do not infer safety or sufficient information from missing data.”
   - **True:** “An explicit adverse signal relevant to buying now is visible in the supplied state.”
   - **False:** “No such explicit adverse signal is visible in the supplied state.”

 False means no explicit adverse signal visible, not adequate data or safety; wording may increase passage of missing-data candidates and has no demonstrated safety or return benefit.
4. **Offline boundary.** Empirical r2 comparison needs previously saved compatible r2 responses. If absent, mark that stage BLOCKED, not zero, PASS or an inferred response; synthetic fixtures only exercise future comparison plumbing. A future model call needs separate approval and is not part of this change's current authorization. Never expose future labels or future-dated input to a model request; the exact historical state and a prompt/response provenance manifest are required. An input snapshot contaminated by future material is ineligible for the paired comparison; changing only the r2 input to filter it would break the exact-input match. Even then, a later model can have hindsight from training, and version drift or unavailable history can invalidate pairability. Historical replay cannot establish prospective or causal performance.
5. **Evidence and lifecycle.** Design makes no claims about function-level control flow; CodeGraph and AST are required before any future implementation touches existing functions. No general dependency framework, new runtime flags or public output-schema change is proposed. Review independently before implementation; do not treat schema artifact completion as repository READY. Formal spec synchronization must preserve a128's existing requirements and resolve the shared capability dependency.

## Risks / Trade-offs

Small, correlated sessions and missing labels limit inference; do not optimize thresholds on this sample. Data quality may correlate with stock and time rather than cause performance. Binary J2 cannot express uncertainty separately. Saved r2 responses may not exist, and a later model may not be comparable. Market-specific unsupported fields must not be mislabeled as collection failure.

## Index synchronization repair

If the advisory stats probe times out, record its failure and skip its index/update; continue to the existing hard index-state recorder. A failed hard sync is never added to the success set. No gate condition, runtime configuration or operating service changes.
