## ADDED Requirements

### Requirement: 읽지 못한 원인은 한 화면에 한 번 설명된다

같은 원인(원장 미판독·브로커 조회 실패·자격증명 없음·seam 미배선·검증 중 갱신 보류·미조회·설정 판독 불가·원장 값 해석 불가)으로 값을 얻지 못한 화면은 그 원인의 설명 문장을 **화면당 1회** 렌더해야 한다(SHALL — 같은 문장이 칸마다 반복되면 운영자는 다른 원인인지 다시 읽어야 한다). 값을 얻지 못한 각 칸은 "미측정" 과 열거된 **사유 코드**를 유지해야 하며(SHALL — 「운영 개요 가시성」의 여덟 사유와 같은 열거), 사유 없는 "미측정" 이나 빈 칸으로 줄여서는 안 된다(SHALL NOT). 설명 문장은 원인과 운영자가 할 일 하나를 적고, 그 값을 채우는 화면이 있으면 링크를 갖는다(SHALL).

#### Scenario: 자격증명 없이 주문 화면을 열면
- **WHEN** Open API 자격증명이 없는 상태로 주문 화면을 열면
- **THEN** 자격증명 없음 설명은 페이지에 1회 나타나고, 일반·조건·합계·종결 각 칸은 "미측정 · 사유 코드" 를 표시한다

#### Scenario: 원장을 읽지 못한 개요
- **WHEN** journal 을 열 수 없는 상태에서 개요를 열면
- **THEN** 원장 미판독 설명은 1회 나타나고 시장별·섹션별 칸은 사유 코드만 반복한다

### Requirement: 알림은 세 단계로만 쓰인다

콘솔의 떠 있는 알림 상자는 두 종류뿐이어야 한다(SHALL): **차단**(기동 거부·읽기 실패처럼 지금 동작이 막힌 사실)과 **결과**(행동에 결과가 따르거나 되돌릴 수 없는 사실). 그 밖의 안내(반영 시점·경계·설명)는 상자가 아니라 일반 본문이나 버튼 옆 한 줄로 렌더해야 한다(SHALL NOT — 모든 안내가 상자면 어느 상자도 눈에 띄지 않는다). 한 화면의 떠 있는 상자는 3개 이하여야 한다(SHALL). 이 분류는 문구를 지우는 것이 아니라 모양을 정하는 것이다(SHALL — 스펙이 요구하는 모든 사실은 계속 렌더된다).

#### Scenario: 저장 버튼 옆 반영 시점
- **WHEN** 설정 폼을 렌더하면
- **THEN** "반영 시점" 안내는 저장 버튼 옆 한 줄 본문이고 떠 있는 상자가 아니다

#### Scenario: 기동 거부
- **WHEN** 기동 인터록 미충족 사실을 렌더하면
- **THEN** 그 사실은 차단 상자로 1회 나타난다

### Requirement: 화면의 경계는 배지와 접힌 블록으로 말한다

각 화면은 제목 옆에 `읽기 전용` 또는 `편집 가능` 배지 하나를 두고(SHALL), "이 화면은 ~하지 않는다" 류의 경계 설명은 접힌 블록 하나(`이 화면의 경계`)로 모아야 한다(SHALL). 경로·navigation 라벨·`<h1>` 의 일치(「화면 이름·경로·제목은 한 화면을 가리킨다」)는 그대로다(SHALL).

#### Scenario: 읽기 전용 화면의 머리
- **WHEN** 포지션 화면을 열면
- **THEN** 제목 옆에 `읽기 전용` 배지가 있고 경계 설명은 접힌 블록 안에 있으며 본문 첫 단락은 데이터로 시작한다

### Requirement: 개발자 식별자는 접힌 기술 정보에 둔다

change ID·settings digest·절대 파일 경로·필드 레지스트리 같은 개발자 식별자는 운영 본문이 아니라 같은 화면의 접힌 `기술 정보` 블록에 렌더해야 한다(SHALL). 값은 DOM 에 남는다(SHALL — 감사와 장애 추적의 증거다). 안전 상태(UNWIRED·OFF·미충족·stale)는 접지 않고 한글 라벨로 항상 보인다(SHALL NOT — 접힌 안전 상태는 숨긴 안전 상태다).

#### Scenario: 최적화 카테고리 라벨
- **WHEN** 최적화 화면을 열면
- **THEN** 카테고리 메뉴의 라벨에 change ID 가 없고, 같은 값은 기술 정보 블록 안에 있다

### Requirement: 상태 표시줄은 칸당 한 줄이다

「콘솔 공통 상태 표시줄」의 네 칸·세 상태·advisory 표기·톤·승인 대기 링크는 그대로이고(SHALL), 칸 안의 설명은 한 줄 이하여야 한다(SHALL). 긴 실패 사유는 사유 코드로 줄이고 전문은 그 화면의 원인 설명(1회)에 둔다(SHALL). 좁은 화면에서는 네 칸이 한 줄 칩 묶음으로 렌더된다(SHALL).

#### Scenario: 브로커 조회 실패의 표시줄
- **WHEN** 브로커 조회가 실패한 상태로 포지션 화면을 열면
- **THEN** 데이터 시각 칸은 "읽지 못함 · 사유 코드" 한 줄이고 영문 원문 오류는 칸 안에 나타나지 않는다
