# a173 — 콘솔 공통 정리(같은 원인 1회 · 경고 3단계 · 경계 배지 · 상태 표시줄 압축 · 내부 식별자 접기)

## 프로그램 개요 (S1~S5, 사용자 지시 2026-10-25)

a172(규칙 20 테마) 배포 뒤 사용자가 `design-critic`·`cognitive-load-assessment` 스킬로 콘솔 GET 화면 전수를 검사하게 했다.
결론: 색·여백·모션은 문제가 아니고 **정보 구조와 글**이 문제다. 다섯 Story 로 나눈다(Story↔change 1:1).

### 사람 결정 기록 (2026-10-25)
1. 설정 탭 축: **가역성·빈도 유지**. `openspec/specs/operator-console/spec.md:851` 이 상시/당일/전략/도구 분류·기본 진입 당일·전략/도구는 진입점만을 SHALL 로 정한다. 검토 보고서의 "5묶음" 권장은 이 스펙과 충돌해 철회했다. 다른 탭 값은 스펙이 요구하는 **읽기 전용 표시 + 링크**로 같은 탭 안에 보인다.
2. 엔진 시작/정지: **검증 콘솔에 그대로**. spec 634·662 가 그 화면의 컨트롤을 줄이지 말라고 SHALL NOT 으로 정한다. 기동 준비 체크리스트(읽기 전용)를 버튼 위에 추가하는 것으로 대신한다(a174).
3. 개발자 정보(change ID·digest·경로·필드 레지스트리): 지우지 않고 **같은 화면의 접힌 "기술 정보"** 로 옮긴다. 감사·장애 추적 증거이고 기존 문자열 시험이 그대로 통과한다. 안전 상태(UNWIRED·OFF·미충족)는 접지 않는다.
4. 빠진 항목 4개: 30일/0일 불일치 → a177, 줄 길이·제목 언어·'적용 후' 표 → a173.

## Why (a173)

2026-10-25 실측(헤드리스 chromium, HEAD `b27a1ea87`, 빈 설정 폴더, 22개 화면 데스크톱 1280 전수 + 모바일 390):
- 같은 원인 문장 반복: `/orders` 자격증명 오류 5회, `/positions` 4회, `/dashboard` `journal_unreadable` 설명 약 8회. 스펙은 "원장 미판독 안내가 페이지에 1회 나타난다"(1442)고 이미 적고 있다.
- 떠 있는 경고 박스: `/settings/daily` 11개, `/settings/standing` 6개, `/dashboard` 5개. "반영 시점 — 다음 엔진 기동부터" 가 저장 버튼마다 박스다. 모두 경고면 아무것도 경고가 아니다(spec 591 의 논리와 같다).
- 모든 화면 머리에 "이 화면은 ~하지 않는다" 문단. 상태 표시줄 칸마다 설명 2줄(데스크톱 약 115px, 모바일 약 400px, `/positions` 모바일은 영문 오류 6줄이 칸에 들어간다).
- 운영 본문에 change ID(`a044`·`a046`·`a047`·`a049`), 절대경로(`/dashboard` 3·`/verify-console` 4), digest, `not_observed`(59회) 노출.
- 본문 한 줄 약 1150px, 영문·한글 혼합 제목, 폼마다 "적용 후 / 실행되는 것" 2행 표 반복.
- 거래 정책 체크박스의 설명이 다음 체크박스에 더 붙어 보인다(근접성 오류, 안전 오독 위험) — a173 은 간격만 고치고 구조는 a174.

## What Changes

1. **원인 1회 규칙**: 화면 단위로 "읽지 못한 원인" 배너를 한 번 렌더(원인 + 할 일 1개)하고, 각 미측정 칸은 `미측정 · <사유 코드>` 만 남긴다. 사유 코드는 spec 1374 의 여덟 열거를 그대로 쓴다(자유 문장 대신 코드). 칸의 사유 표시(spec 706·716)는 유지된다.
2. **알림 3단계**: `bad`(기동 거부·읽기 실패 같은 차단) / `warn`(행동에 결과가 따름) / 일반 글(그 외). "반영 시점" 류는 버튼 옆 한 줄 `muted` 문장. 한 화면의 떠 있는 박스 ≤ 3.
3. **경계 배지**: h1 옆 `읽기 전용`(또는 `편집 가능`) 배지 하나 + 접힌 `이 화면의 경계` 블록 하나로 머리 문단을 대체. 경로·nav·h1 일치(spec 632)는 그대로.
4. **상태 표시줄 압축**: 네 칸·세 상태·advisory 표기·톤·승인 대기 링크(spec 574~612)는 유지하고 칸 안 설명은 1줄 이하(긴 사유는 `title` + 데이터 시각 칸의 "읽지 못함 · 사유 코드"). 모바일은 한 줄 칩 묶음. 데스크톱 ≤ 72px, 모바일 ≤ 120px.
5. **기술 정보 접기**: change ID·digest·절대경로·필드 레지스트리를 `<details class="tech">` 로. 값은 DOM 에 그대로.
6. **줄 길이·제목·'적용 후' 표**: 산문 블록 `max-inline-size: 42rem`(표·폼은 제외), 섹션 제목은 한글 우선(영문 식별자는 `<code>`), "적용 후/실행되는 것" 표는 저장 버튼 옆 한 줄 문장으로.
7. **거래 정책 체크박스 간격**: 설명이 자기 체크박스와 같은 블록 안에 보이도록 여백만 조정(a174 가 구조를 바꾼다).

## Scope / Non-goals

- 범위: `internal/console/` 의 템플릿(`templates*.go`)·뷰 모델 헬퍼(사유 코드·배너 데이터 제공)·`{{define "style"}}` CSS·시험, `docs/console-design.md`(알림 3단계·경계 배지·기술 정보 규칙 추가), 이 change 의 `measure/` 하네스.
- 비목표: 라우트·핸들러·POST 필드·CSRF·audit·CSP·자동 재로드 주기·브로커 호출·설정 저장 의미(spec 851 "분류는 저장 의미를 바꾸지 않는다")·a058 보유 표 밀도·탭 축·버튼 위치. 설정 레이아웃(a174)·최적화/전략 행렬(a175)·개요 요약 재배치와 `/verify`(a176)·30일 값(a177)은 여기서 하지 않는다.
- 고정 리터럴 시험: 바꿔야 하면 a172 와 같이 `tasks.md` 「고정 리터럴 시험 수정 기록」에 사유와 함께 전수 기록. 문자열 삭제가 아니라 위치 이동이므로 대부분은 그대로 통과해야 한다.
