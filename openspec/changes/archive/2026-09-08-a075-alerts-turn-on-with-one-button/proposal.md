# a075 · 알림은 버튼 하나로 켜진다

## 왜

a074는 전송 경로를 **설정 가능**하게 만들었다. 그리고 거기서 멈췄다. 지금 알림을
켜려면 운영자가 이 두 가지를 손으로 해야 한다.

```jsonc
// ~/.config/tossctl/<profile>/config.json 을 직접 열어서
"engine": {
  "notifications": { "enabled": true, "base_url": "https://ntfy.sh", "topic": "???" }
}
```
```bash
# 그리고 컨테이너 환경에
TOSSCTL_NTFY_TOKEN=???
```

`topic`에 무엇을 써야 하는지 아무 화면도 말해주지 않는다. 좋은 topic이 무엇인지 —
ntfy.sh에서는 topic 이름이 **유일한 접근 제어**이므로 추측 가능한 이름을 쓰면 계좌
이벤트가 공개된다 — 는 사실은 a074의 소스 주석에만 있다. 토큰은 self-hosted ntfy가
아니면 애초에 필요 없는데도 이름이 노출되어 있어 "이것도 채워야 하나"를 만든다.

즉 **가장 중요한 안전 스위치가 가장 손대기 어려운 경로에 남아 있다.** 이것은
`console-owns-the-operating-toggles`가 자동화 게이트에 대해 이미 한 번 내린 판단과
같은 모양이다.

> "그 배제가 실제로 산 것은 안전의 반대였다. 손편집 경로는 아무것도 확인하지 않는다:
> 다섯 한도가 설정됐는지, JSON이 여전히 파싱되는지, 운영자가 무엇이 시작되는지 아는지
> — 그리고 audit 줄을 하나도 남기지 않는다."

알림 설정에도 그대로 적용된다. 손편집 경로는 topic의 엔트로피를 확인하지 않고,
JSON을 검증하지 않고, 전송이 실제로 되는지 알려주지 않고, audit에 남기지 않는다.

## 무엇을

**설정 화면에 알림 카드를 만들고, 그 카드의 버튼 하나가 전부를 한다.**

`[알림 켜기]` 한 번에:

1. 추측 불가능한 채널 주소를 **만든다** — `crypto/rand` 128비트. 운영자가 topic을
   고르지 않으므로 나쁜 topic을 고를 수 없다.
2. `engine.notifications`의 세 키만 **기록한다** — `enabled`·`base_url`·`topic`.
   기존 저장 경로와 같은 flock·원자적 rename·surgical splice.
3. audit에 **남긴다** — 켜짐/꺼짐, 서버 주소, 채널·자격증명의 **설정 여부**.
   채널 주소 자체는 남기지 않는다 (§0.8, a074가 정한 계약).
4. 그 채널로 테스트 알림을 **한 통 보낸다** — 콘솔 프로세스가 직접. 엔진 재시작을
   기다리지 않고 "이게 도착하나"를 즉시 답한다.

그리고 화면이 구독 주소를 보여준다. 운영자가 할 일은 그 주소를 여는 것뿐이다.

**토큰은 화면에 없다.** self-hosted ntfy를 쓰는 운영자는 지금처럼
`TOSSCTL_NTFY_TOKEN`을 환경에 넣으면 되고 (a074 경로 그대로 유효),
공개 ntfy.sh를 쓰는 운영자에게는 토큰이 필요 없다 — 128비트 주소가 곧 자격이다.

## 무엇을 하지 않는가

- **알림을 자동으로 켜지 않는다.** 기본값은 여전히 off이고, 버튼을 누르는 것은
  사람이다 (§0.7). 이 change는 그 사람이 누를 것을 만들 뿐이다.
- **엔진의 알림 조립 경로를 바꾸지 않는다.** `resolveNotificationPublisher`는
  a074가 쓴 그대로다 — 파일의 topic을 이미 읽으므로 고칠 것이 없다.
- **`obs.Notifier`·outbox·entry gate latch·등급표를 건드리지 않는다.** 테스트 발송은
  outbox를 거치지 않는 단발 publish이고, 실패해도 latch하지 않는다.
- **밀린 outbox 행을 자동으로 비우지 않는다.** `Notifier.Flush`는 아직 호출자가
  없고, 그 배선은 자기 위험 분석이 필요한 별개 change다 (issues I3).
- **토큰 입력 필드를 만들지 않는다.** 설정 파일에 토큰 자리를 만들지 않는다는
  a074의 구조적 결정을 화면에서도 유지한다 — 입력할 곳이 없으면 붙여넣을 수 없다.
- **타이핑 확인·2단계 승인을 넣지 않는다** (사용자 지시 2026-07-27).
