### 왜 이 문을 잠그는가

임차를 승인 술어에 넣으면(`AND claim_token = ''` 따위) 이렇게 된다.

| | |
|---|---|
| 발송자가 들고 있는 행을 운영자가 승인하려 한다 | **0행 → 오류** |
| `notifier.go:500`이 오류를 본다 | 승인이 실패한다 |
| 운영자가 받은 알림을 **해제할 수 없다** | 최대 54초 |
| 진입 게이트가 그동안 **안 풀린다** | 불변식 4 방향으로 나쁘다 |

**운영자의 승인은 발송자의 임차보다 우선한다.** 사람이 봤다는 사실이 기계의 진행 중
상태에 막히면 안 된다.

## 재무장 상호작용 — 여기 적는 이유

이 함수가 만든 ACKNOWLEDGED 행은 나중에 `ClaimAlertForDelivery`가 재무장한다.
그 UPDATE(`outbox.go:229-236`)가 **임차 열을 초기화하지 않으면 재무장된 행이 이전
episode의 임차를 달고 태어난다.** a097의 원칙(`:198-201`의 주석) 위반이다.

**그 검증은 이 번들이 아니라 `claimalertfordelivery` 번들과 tasks 4.6의 몫이다.**
여기 적는 이유는 이 함수가 **그 상황을 만드는 쪽**이기 때문이다.
