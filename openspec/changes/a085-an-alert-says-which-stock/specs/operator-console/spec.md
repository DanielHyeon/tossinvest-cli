# operator-console — a085 delta

> **ADDED만 쓴다.** 근거 없는 값을 0으로 그리지 않는다는 기존 fail-closed 표시 계약은
> 그대로다. a085는 격리가 그 계약의 어느 쪽인지만 확정한다 — 격리는 "근거가 없다"가
> 아니라 "근거가 고정됐고 그 값이 무엇인지 알려져 있다"이다.

## ADDED Requirements

### Requirement: 판정 격리된 포지션은 자신이 붙들고 있는 기준선을 보여준다

exit snapshot이 격리된 포지션의 화면은 저장된 진입가·최초 손절·현재 보호선·워터마크를 보여주어야 한다(SHALL).
이 값들은 원장에 존재하고 갱신이 멈춰 있을 뿐이며, 감추는 것은 운영자에게서 "이 포지션이
무엇을 붙들고 있는가"라는 답을 빼앗는다.

같은 사실을 다루는 화면들은 서로 모순되어서는 안 된다(SHALL NOT). 포지션 관리 화면이
유지 중인 보호선을 제시하는 포지션에 대해 포지션 화면이 값 없음으로 표시해서는 안 된다.

표시된 값은 **갱신되지 않는 저장값**임이 화면에서 구별 가능해야 한다(SHALL). 살아 있는
보호선과 얼어 있는 보호선을 같은 모양으로 그려서는 안 된다(SHALL NOT).

격리된 포지션이 판정 대상이 아니며 손절도 평가되지 않는다는 경고는 유지해야 한다(SHALL).

이 요구사항은 다른 사유의 표시 규칙을 바꾸지 않는다(SHALL NOT). 엔진 미실행·관측
노후·불완전 tuple 등 "값을 신뢰할 수 없다"에 해당하는 사유는 기존대로 값을 감춘다.

#### Scenario: 격리된 포지션의 포지션 화면
- **WHEN** 판정 격리된 포지션이 포지션 화면에 그려진다
- **THEN** 저장된 진입가·최초 손절·현재 보호선·워터마크가 제시되고, 갱신되지 않는 저장값임이 함께 표시되며, 판정 대상이 아니라는 경고가 유지된다

#### Scenario: 두 화면의 일치
- **WHEN** 포지션 관리 화면이 어떤 포지션의 유지 보호선을 제시한다
- **THEN** 포지션 화면도 같은 포지션에 대해 같은 보호선을 제시한다

#### Scenario: 값을 신뢰할 수 없는 사유
- **WHEN** 엔진 미실행이나 관측 노후로 exit line이 stale로 판정된다
- **THEN** 기존대로 값을 감추고 사유만 제시한다
