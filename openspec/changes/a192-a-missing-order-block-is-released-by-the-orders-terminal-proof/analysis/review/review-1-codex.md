## 응답
References to `design.md`, `proposal.md`, and `delta` mean files under `openspec/changes/a192-a-missing-order-block-is-released-by-the-orders-terminal-proof/`.

1. **BLOCKER — Creation provenance does not protect against later producers sharing the row.**  
   `at_entry=1` proves who created the row, not what subsequently depends on it. A later projection refusal finds the existing symbol row and returns without recording its cause (`internal/journal/position_projection.go:385–405`). Oversells use `QUANTITY_MISMATCH`; other refusals use `ATTRIBUTION_FAILED` (`:428–432`). Consequently, an originally eligible missing-order row can conceal either kind of refusal and still satisfy C2/C3. The next quantity comparison is not guaranteed to expose an attribution failure. `design.md:337` acknowledges only oversell and assumes subsequent comparison will usually catch it.  
   **Change:** Every producer encountering an existing row must atomically record disqualifying provenance. Cover missing-order-first → oversell/attribution-refusal → coincidental agreement, not merely other-producer-first.

2. **BLOCKER — W2 can lose evidence without the documented “write failure + restart” sequence.**  
   W2 runs after persistence (`design.md:248`), but `Observe` can return earlier on pending-permanent authority failure (`internal/reconcile/mismatch.go:689–713`). A quantity dispute against an existing eligible symbol row is then neither appended nor marked `quantityUnwritten`. Separately, W2 explicitly skips pending rows and only preserves failed **quantity** writes in memory (`design.md:202–206`). Failed missing-order attachments have no equivalent protection. The existing block map retains the first block rather than merging subsequent evidence (`mismatch.go:719–724`). A later clean comparison can therefore release using an incomplete history—even without restarting.  
   **Change:** Accumulate all disqualifying observations and missing-order identities before any early return, retain them across pending retries, and persist them atomically with eligibility. Add authority-error, missing-binding-write-error, and pending-row scenarios.

3. **BLOCKER — Verdict reads and release commit have no common consistency boundary.**  
   D3 reads bindings and fill snapshots, then D5 calls ordinary `ReleaseReconcile` (`design.md:207–253`). That method rechecks only active scope and cause, not the inspected row ID, bindings, terminal snapshots, or projection version (`internal/journal/reconcile_states.go:286–301`). `Observe` and `Refresh` share a mutex, but fill detection commits `RecordFill` **before** acquiring it through `Refresh` (`internal/filldetect/ledger.go:80–85`). Thus a fill/projection refusal can commit after the verdict read, while refresh waits, and the stale verdict can still release the row. A terminal snapshot can also become `fail_closed` (`internal/journal/fills.go:833–857`).  
   **Change:** Run the pure verdict against reads inside the release transaction, or conditionally commit against exact row/binding/fill/projection versions. Test a controlled writer interleaving between proof read and release.

4. **MAJOR — C5 checks historical equality, not whether lineage subsequently moved.**  
   C5 compares the two IDs stored at attachment time (`design.md:222`). `LocalStateFromJournal` resolves current lineage dynamically (`internal/reconcile/compare.go:213–227`), whereas the proposed binding is append-only. Example: bind `A/A`; amend to `B`; record A terminal; B remains live and matches the broker. B need not appear in either missing orders or external orders because matched orders are excluded (`compare.go:454–479`). C5 still passes, and C10 checks A only. This violates the delta’s “lineage moved → retain” requirement (`delta:31–33`).  
   **Change:** Resolve current scoped lineage at verdict time and require it to remain unchanged, within finding 3’s consistency boundary. Test amendment **after** binding.

5. **MAJOR — Account authority is checked on the row, but not on the comparison or bindings.**  
   C1 requires row account = tracker account; C4 only requires nonempty binding components (`design.md:218–228`). Yet ordinary blocks deliberately accept foreign-account observations: `blocksFor` assigns the tracker account while taking the missing order’s symbol (`internal/reconcile/mismatch.go:1418–1429`). Existing tests explicitly preserve these fail-closed blocks (`internal/reconcile/a110_missing_order_incident_test.go:160–178,182–200`). A foreign binding’s terminal snapshot—or a clean foreign-account `Diff`—can satisfy the proposed release conditions.  
   **Change:** Require nonempty canonical equality among tracker, row, binding, and comparison accounts; require binding symbol = row symbol. Invalid observations may block but must never authorize release.

6. **MAJOR — `CommittedAt` is not proof that collection started after commit.**  
   C8 treats `AsOf > CommittedAt` as causal ordering (`design.md:225,234–235`). `RecordFill` captures its timestamp **before** beginning the transaction (`internal/journal/fills.go:333–339`), adjusts that timestamp at `:373`, and commits only after hooks at `:551–556`. Snapshot collection can begin between timestamp capture and commit, yet later pass C8. Sharing a clock does not close this window. `Diff.AsOf` also drops fractional seconds (`internal/reconcile/compare.go:362`), introducing conservative delays.  
   **Change:** Establish a committed journal watermark before collection and require the proof to belong to that already-visible watermark; revalidate relevant state at release. Document timestamp precision separately from causal guarantees.

7. **MAJOR — Existing regression tests can remain green while the production release path is unsafe.**  
   D4 deliberately leaves existing test trackers with `Terminal == nil` (`design.md:245`), and the proposed compatibility test exercises that disabled state (`:362`). `TestACoincidentalAgreementStillDoesNotRelease` creates a quantity mismatch and asserts retention (`internal/reconcile/converge_test.go:153–169`); running it without the new reader does not verify that the enabled feature preserves its guarantee. The listed tests also omit the interleavings and later-producer cases above (`tasks.md:28–37`).  
   **Change:** Run the relevant a083/a110 safety scenarios with the terminal reader enabled and real journal bindings. Add crash boundaries between W1/W2 and enabled-path tests for foreign identities, later lineage, and concurrent refusal. Preserve the operator-only CLI tests separately.

8. **MINOR — The “schema change required” argument excludes a viable alternative without evaluating it.**  
   Q7 rejects deriving provenance from existing data and parsing existing prose (`design.md:115–118`). Neither rules out writing a **new, versioned structured payload** into the existing `evidence` field. That field accepts arbitrary nonempty text and is written transactionally (`internal/journal/reconcile_states.go:175–188,214–222`).  
   **Change:** Compare the new table against a versioned evidence envelope containing identities and monotone disqualification state, atomically updated by every relevant producer. Treat legacy/malformed envelopes as ineligible. This avoids migration but still requires findings 1–3’s transactional changes; merely parsing today’s prose or retaining process memory does not satisfy restart consistency.

9. **NIT — One AST call attribution is wrong.**  
   `design.md:53,88` identifies `logCycle call@545`. Line 545 actually calls `d.opts.Log.Event`; `Run` calls `d.logCycle` at line 402 (`internal/app/engine/reconcileloop.go:402,545`). The supplied AST agrees: `analysis/cited-ast/internal-app-engine--reconciledriver.logcycle.ast.json:62–65`.  
   **Change:** Cite `Run → logCycle(call@402) → Log.Event(call@545)`.

The delta’s unconditional restart/provenance requirements (`delta:7,31–33`) contradict D2’s admitted loss, while the unchanged durable-release and permanent-operator requirements remain compatible (`openspec/specs/reconciliation/spec.md:226–228,269–279`). The exit concern is also substantiated: covering blocks activate two retried reads, and floor errors yield zero (`exitwiring.go:197–240`; `exitloop.go:1760–1768`); repository search found no production `ExitAllowed` caller. Broker-zero explicitly rejects the new cause (`risk_bucket_owner.go:279–281,676–677`), so its recovery limitation needs an explicit disposition.
