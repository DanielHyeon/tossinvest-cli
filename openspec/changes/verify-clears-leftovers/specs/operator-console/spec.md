# operator-console Specification (delta)

## ADDED Requirements

### Requirement: 끝난 실행이 다음 실행을 막지 않는다

검증 화면은 끝난 실행이 화면에 남아 있어도 시작 제어를 계속 보여주어야 한다(SHALL).
아무것도 전송하지 않고 끝난 실행 뒤에 콘솔 재시작 말고는 다시 시도할 방법이 없어서는
안 된다(SHALL NOT). 시작 제어는 이어하기·재측정 버튼을 말한다.

기존 가드는 그대로 적용된다(SHALL): 프로세스가 이미 검증을 수행했으면(`Spent`) 버튼은
비활성이고, 이어할 단계가 없으면 비활성이다. **진행 중인** 실행이 있는 동안에는 시작 제어를
보여주지 않는다(SHALL NOT) — 그 상태에서 필요한 조작은 승인이나 거부다.

근거: 2026-07-27 장중에 승인 창 만료 세 번이 각각 콘솔 재시작을 요구했고, 그 사이 US
정규장 창이 소진됐다(measurements.md M11·M18).

#### Scenario: 0단계로 끝난 실행 뒤 다시 시도

- **WHEN** 승인 창이 만료되어 아무것도 전송하지 않고 실행이 끝났으면
- **THEN** 검증 화면은 `[이어하기]`를 다시 제공한다

#### Scenario: 진행 중인 실행에서는 시작 제어가 없다

- **WHEN** 실행이 승인을 기다리거나 단계를 걷고 있으면
- **THEN** 시작 제어는 표시되지 않는다

### Requirement: 잔여물이 있으면 이어하기는 무동작이 아니다

정리 대상이 남아 있으면 이어하기를 거부해서는 안 된다(SHALL NOT — 모든 단계가 terminal이어도).
그 실행은 보낼 라이브 요청(취소)이 있으므로 무동작이 아니다. 화면과
서버 가드는 같은 판정을 써야 한다(SHALL) — 버튼만 열려 있고 서버가 거부하거나 그 반대여서는
안 된다.

#### Scenario: 판정이 모두 끝났지만 잔여물이 있다

- **WHEN** 모든 단계가 terminal이고 이 도구가 만든 미체결 주문이 기록에 살아 있으면
- **THEN** 이어하기가 제공되고, 시작하면 그 취소가 승인 목록에 오른다

#### Scenario: 판정이 모두 끝났고 잔여물도 없다

- **WHEN** 모든 단계가 terminal이고 잔여물도 없으면
- **THEN** 이어하기는 종전대로 무동작으로 거부된다

### Requirement: 승인 만료 문구는 실제 승인 방식을 말한다

콘솔 승인이 만료되었을 때의 문구는 **화면의 클릭**을 가리켜야 한다(SHALL). 존재하지 않는
확인 문자열을 가리켜서는 안 된다(SHALL NOT).

#### Scenario: 콘솔에서 만료

- **WHEN** 콘솔에서 시작한 실행의 승인 창이 만료되면
- **THEN** 기록과 화면의 사유는 클릭 승인이 만료되었다고 말한다
