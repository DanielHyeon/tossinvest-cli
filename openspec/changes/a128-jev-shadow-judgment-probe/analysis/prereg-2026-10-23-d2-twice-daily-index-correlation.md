# a128 사전등록 D2 — 하루 두 번 무조건 가상 매수 × 지수 등락 상관 (2026-10-23)

- 결정: 사용자 2026-10-23 02시대(Manager 전달, 「권장」 전부 채택). 같은 날 앞서 논의한 「하락장 X% 팔(R0·R1·R2)」은
  **취소**되어 등록하지 않음(사용자 설계 변경 — 이 문서가 그것을 대신함).
- 이 문서는 **판정 창의 첫 데이터(2026-10-23 KR 세션, 10:00 KST 진입)가 생기기 전에** 커밋함. 커밋 시각이 규칙 고정
  시각의 증거임. 평가기 구현(`prereg_eval.py` 의 D2 갈래)은 이 문서 커밋 **뒤에** 이어서 함 — 구현은 이 문장을
  옮길 뿐 규칙을 바꾸지 않음. 문장과 구현이 갈리면 이 문서가 정본임.
- 이후 규칙·구간·비용·창·판정 조건을 바꾸지 않음. 바꾸면 새 사전등록이고 새 창이 필요함.
- 기존 사전등록 `prereg-2026-10-22-j2-warning-hypotheses.md`(H-KR·H-US·F-KR·F-US·맞대결)는 **한 글자도 바꾸지 않음**.
  D2 는 그와 독립한 별도 분석이며 그 판정에 영향을 주지 않음. 평가기에 D2 를 넣을 때 기존 네 팔의 출력은 같은 입력에서
  편집 전후 바이트가 같아야 함(대조 영수증을 남김).
- 성격: 오프라인 분석. 가상 매수만 셈 — **실주문 0**, 주문·계좌·운영 토글과 무관. 결과는 수익성 결론이 아니며
  어떤 거래의 근거도 아님.

## 1. 데이터와 공통 정의

- 원장·state·1분봉 합집합·`pick_close` 관례는 10-22 사전등록 1절과 같음(원장 읽기 전용, 1분봉 라벨은 **KST 시계**,
  같은 라벨 봉은 가장 늦게 관측한 state 값, 세션 날짜 = 판단 시각 `at` 의 UTC 날짜).
- 판단 행은 `kind=judgment`, `question_id=j2_hold_off_red_flag` 만 씀.
- 비용(10-22 사전등록 3절, 저장소 `costs.DefaultModel()` 값): **KR 왕복 0.50%, US 왕복 2.10%**. 순수익률 = 총수익률 − 왕복 비용
  (거래당 1회 차감).

## 2. 대상 — 종목 목록 고정 (규칙 1·7)

- **KR 목록**: 세션 날짜마다, 판단 시각 `at` 이 KST **10:00:00 이상 10:10:00 미만**인 J2 판단을 받은 종목 전부
  (프로브의 10:00 회차 = 보통 30종목). 그 회차가 없으면 그날 KR 은 목록 없음 → 그날 KR 두 진입 모두 결측.
- **US 목록**: 세션 날짜마다, `at` 이 미국 동부시(America/New_York, 서머타임 자동 반영) **10:00:00 이상 10:10:00 미만**인
  J2 판단을 받은 종목 전부. 없으면 그날 US 두 진입 모두 결측.
- 13:00 진입도 **같은 목록**을 씀(13:00 회차에 새로 판단된 종목은 넣지 않음).
- 목록 종목 하나 = 진입 시각마다 가상 매수 1건(신호 여부와 무관한 **무조건** 매수).
- 신호 갈래(보조 분석용): 그 종목의 **목록 회차 J2 판단** `p >= 0.6` 이면 「신호」, 아니면 「비신호」. 13:00 진입도 이 분류를 그대로 씀.

## 3. 진입·청산 (규칙 2·3)

- 가격 = 1분봉 종가. 목표 시각 T 의 라벨 봉 종가, 없으면 **[T−5분, T]** 안 가장 가까운 이전 봉 종가
  (H-KR 의 `pick_close` 관례). 그것도 없으면 그 거래는 결측(진입 결측 / 청산 결측으로 사유를 세어 보고).
- **KR**: 진입 T = 10:00 KST, 13:00 KST. 청산 T = **14:10 KST**(두 진입 공통).
- **US**: 진입 T = 10:00 ET, 13:00 ET. 청산 T = **각 진입 + 60분**(11:00 ET, 14:00 ET).
  봉 라벨은 KST 시계이므로 T 를 KST "HH:MM" 로 바꿔 찾음. US 봉은 KST 자정을 넘으므로 창 비교는 문자열이 아니라
  **시각(타임스탬프)** 으로 함(예: 11:00 EDT = 00:00 KST 의 [23:55, 00:00] 창).
- 봉 출처 우선순위:
  1. 원장 state 의 1분봉 합집합(주식-일 = market, 세션 날짜, symbol).
  2. 1에서 [T−5분, T] 봉을 못 찾을 때만 — **공식 1분봉 영수증 파일**
     `analysis/d2-receipts/minute-bars/<MARKET>-<YYYY-MM-DD>.json`(공식 Open API 종목 1분봉을 읽기 전용으로 조회해 고정한 것).
     평가기는 네트워크를 쓰지 않고 이 파일만 읽음. 파일이 없거나 그 봉이 없으면 결측.
  - 영수증 조회는 평가 시점(또는 세션 뒤)에 사람이 승인한 읽기 전용 명령으로 하며, 호출 수를 세어 영수증에 같이 적음
    (D11 조회 예산 보고용). 운영 중인 a128 타이머·러너·원장 기록 경로는 바꾸지 않음.
  - 출력에 봉 출처별 건수(state / 영수증 / 결측)를 보고함.

## 4. 진입 시각 지수 등락 (규칙 4)

- **KR = KOSPI**: state 의 `market_context.indices[]` 중 `symbol == "KOSPI"` 인 항목의 `change_today_pct`.
- **US = S&P 500**: state 의 `market_context.major_indices[]` 중 `code == "SPX.CBI"`(이름 「S&P 500」) 인 항목의 `change_pct_vs_base`.
- 값을 고르는 법: 그 시장·세션 날짜의 state(종목 무관) 중 **관측 시각 `observed_at` ≤ 진입 시각 T** 이고 위 값이 있는 것 가운데
  **가장 늦은 것**. 차이(분) = T − observed_at 을 같이 기록함.
- **허용 차이 상한 10분**(프로브 회차 간격 600초). 차이 > 10분이거나 그런 state 가 없으면 그 (시장, 진입 시각, 날짜) 의
  지수 값은 결측 → 그 날짜·진입은 주 분석·보조 분석 모두에서 **제외**(판정 불가로 셈, 수를 보고).
- 진입 시각에 이미 관측된 값만 씀(당일 종가 등 진입 뒤 값은 쓰지 않음).

## 5. 비교 (규칙 5)

- 지수 구간(단위 %, 값 v): **B1: v ≤ −3**, **B2: −3 < v ≤ −1**, **B3: −1 < v < 0**, **B4: v ≥ 0**.
- **주 분석 — 날짜 단위**: 분석 칸 = (시장, 진입 시각) 네 개 — KR-10:00, KR-13:00, US-10:00, US-13:00 — 각각 따로.
  - 날짜 표본 하나 = 그 칸의 한 세션 날짜. 값 = 그날 목록 종목 중 결측 아닌 거래의 **순수익 단순 평균**(종목 동일 가중),
    짝 = 그날 그 진입 시각의 지수 등락 v. 유효 거래 0건이거나 v 결측이면 그 날짜는 표본에서 빠짐.
  - 같은 날 종목들은 같은 지수 값을 공유해 독립 표본이 아니므로 **판정과 상관은 날짜 단위로만** 함.
  - 보고: 날짜 수, 구간별 날짜 수와 날짜 평균 순수익의 평균, 스피어만 ρ(지수 등락 v 대 날짜 평균 순수익, 동순위는 평균 순위,
    날짜 3개 미만이면 「-」).
- **보조 분석 — 종목 단위**(서술용, 판정 아님): 같은 칸에서 거래 하나를 표본으로 한 스피어만 ρ 와 구간별 평균 순수익.
  갈래별로도 보고 — 신호/비신호 × 유형(STOCK / ETF / ETN / 기타 / 미분류). 이 갈래들은 판정에 쓰지 않음.

## 6. 가설과 판정 (규칙 6)

- **사용자 가설**: 「지수가 많이 떨어진 날(B1, ≤ −3%)이 덜 떨어진 날(B3, (−1%, 0%))보다 순수익이 높다.」
- 판정은 4개 칸(KR-10:00, KR-13:00, US-10:00, US-13:00) 각각 따로, **전체 목록 종목**(신호·비신호·모든 유형 합침)으로:
  - B1 날짜 수 < 5 **또는** B3 날짜 수 < 5 → `INSUFFICIENT`.
  - 그 밖: (B1 날짜들의 날짜 평균 순수익의 평균) **>** (B3 날짜들의 날짜 평균 순수익의 평균) 이면 `SUPPORTED`, 아니면 `NOT_SUPPORTED`.
  - 스피어만 ρ(날짜 단위)의 부호와 값을 **함께 보고**함 — 가설 방향은 ρ < 0(지수가 더 떨어질수록 순수익이 높음).
    ρ 는 판정 조건이 아니라 보고 항목임.
- 네 칸을 따로 판정하므로 다중 비교 보정은 하지 않음 — 칸 하나의 `SUPPORTED` 를 일반화하지 않음.
- `SUPPORTED` 는 추가 그림자 시험을 설계할 근거일 뿐 수익성 결론이 아님.

## 7. 유형 판별 — ETF·ETN 분리 (규칙 1·8)

- 출처: 공식 Open API `GET /api/v1/stocks` 응답 `StockInfo.securityType`(required). enum 전체
  (`docs/migration/openapi.latest.json` `components.schemas.StockInfo.properties.securityType`):
  `STOCK, FOREIGN_STOCK, DEPOSITARY_RECEIPT, INFRASTRUCTURE_FUND, REIT, ETF, FOREIGN_ETF, ETN, STOCK_WARRANTS`.
- 갈래 대응(사전 고정):
  - **STOCK** = `STOCK`, `FOREIGN_STOCK`
  - **ETF** = `ETF`, `FOREIGN_ETF`
  - **ETN** = `ETN` (ETF 와 따로 셈)
  - **기타** = `DEPOSITARY_RECEIPT`, `INFRASTRUCTURE_FUND`, `REIT`, `STOCK_WARRANTS`
  - **미분류** = 위 enum 밖의 값, 조회 실패, 응답에 종목 없음, 영수증 파일 없음
- 입력: 영수증 파일 `analysis/d2-receipts/security-types.json` (`{"<symbol>": "<securityType>"}` 와 조회 시각·호출 수).
  평가기는 네트워크를 쓰지 않음.
- 현재 tossctl 은 이 값을 출력하지 않음(실측 2026-10-23: `tossctl ops call stocks` 응답이 `symbol, name, market_code, currency,
  status, fetched_at` 뿐 — `internal/official/stock_reads.go:37` 이 받지만 `domain.Quote` 에 칸이 없음). 이를 드러내는 변경은
  **후속 change(a169) 범위**이고 이 분석은 생산 코드를 바꾸지 않음. **그 전까지 영수증 파일이 없으면 모든 종목을 「미분류」로 셈.**
  유형은 보조 분석 갈래일 뿐 판정(6절)에 쓰이지 않으므로 판정은 영향받지 않음.

## 8. 창과 정지 (규칙 9)

- **KR**: 세션 날짜(KST) **2026-10-23 ~ 2026-12-24**. 12-24 = a128-kr 타이머를 미리 꺼야 하는 다음 KR 휴장일
  12-25(`docs/handoff/2026-10-19-manager-handoff.md:134`) 전 마지막 KR 세션.
- **US**: 세션 날짜(UTC = 개장일) **2026-10-23 ~ 2026-12-24**.
- 10-22 이전 데이터는 넣지 않음.
- 휴장·조기 폐장·프로브 실패로 목록·봉·지수가 없는 날은 규칙대로 결측(대체 날짜 없음). 예: US 11-26 휴장, 11-27·12-24
  13:00 ET 조기 폐장 → 13:00 진입의 청산 봉(14:00 ET) 없음 → 결측.
- 타이머가 창 끝 전에 꺼지면 그 뒤 날짜는 데이터가 없을 뿐 창은 바뀌지 않음.
- **판정은 창 끝 뒤 한 번**(US 12-24 세션의 13:00 ET + 60분 청산이 지난 뒤 평가기를 돌린 결과). 창 끝 전의 실행은 모두
  **중간 집계 — 서술용이며 판정 아님**. 평가기는 창 끝 전 실행의 판정 칸을 「중간 집계(판정 아님)」로 표시함.
  중간 집계에서 B1·B3 날짜 수가 5에 닿아도 그때 판정하지 않음(중도 정지 없음).

## 9. 알려진 한계 (사전 기록)

1. **생존 편향·결측**: 프로브의 종목 집합은 10분마다 순위로 바뀌므로 10:00 목록 종목이 13:00·14:10 관측에 없으면 그 봉이 state 에
   없음(10-22 사전등록 7절 4항과 같은 구조). 영수증 보충이 없으면 13:00 진입과 청산 결측이 클 수 있음.
2. **영수증 보충의 한계**: 현재 CLI 의 종목 차트 명령 `tossctl quote chart <symbol> --interval 1m --count N`(`cmd/tossctl/quote.go:148`)은
   `count` 상한 200(API 400 `constraint max 200` 실측)이고 `before` 인자가 없어 **최근 200분만** 줌(KR 은 NXT 시간외 봉까지 포함 —
   2026-10-23 02시 실측 결과 마지막 봉 20:00 KST). 그래서 세션 뒤에 지난 시각 봉을 채우려면 `before` 를 받는 공식 1분봉 조회
   (프로브가 쓰는 `StrictMinuteCandles(ctx, market, symbol, count, before)`)가 필요함 — 그 읽기 전용 조회 도구는 평가기 구현 단계에서
   정함. 도구가 없거나 API 가 그 날짜를 주지 않으면 보충 없이 결측으로 셈(규칙 불변).
3. 10-23~10-28 은 10-22 사전등록(H-KR 등)의 표본 외 창과 겹침 — D2 는 그 판정에 쓰이지 않으며 그 반대도 같음.
4. 지수 값은 프로브 state 의 스냅숏(공식 지수 조회값)이지 진입 1분봉 종가가 아님. 차이(분)를 보고해 확인 가능하게 함.
5. KR 과 US 의 지수 등락은 서로 상관될 수 있음 — 칸을 합치지 않음.
