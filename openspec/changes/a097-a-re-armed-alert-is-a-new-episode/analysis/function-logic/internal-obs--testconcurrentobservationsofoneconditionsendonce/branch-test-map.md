# Branch Test Map: `TestConcurrentObservationsOfOneConditionSendOnce`

측정: `go test -covermode=set -coverprofile ./internal/obs/` — GREEN 총계 **86.7%**
(RED 85.4%). 이 함수는 테스트이므로 커버리지 대상이 아니다. 아래의 RED/GREEN 칸은
**뮤테이션 실측**이며, 그것이 테스트 함수에 대해 의미 있는 유일한 측정이다.

뮤턴트: `claimAndDeliver`의 `n.mu.Lock()`/`defer n.mu.Unlock()` 제거. `GOMAXPROCS=1`,
각 100회.

## 이 표가 말하는 것

원본 테스트는 이미 뮤턴트를 96%는 잡았다. 놓친 4%가 a096 리뷰가 본 오통과다.

**리뷰가 처방한 barrier는 그것을 고치지 않았다** — barrier만 넣은 변형은 91/100으로
오히려 낮았고, 차이는 1.4σ라 잡음과 구분되지 않는다. 고친 것은 `B3`의 근거가 된
차단 publisher다: 첫 전송을 `Publish` 안에 붙잡으면 경합 창이 우연이 아니라 구성으로
열리고, 두 번째 진입이 관측 가능한 **사건**이 된다.

barrier는 유지한다. 탐지에는 기여하지 않지만 비용이 없고, `ready.Wait()`가 "여덟 관측이
동시에 출발했다"를 참으로 만들어 준다. 그것이 없으면 이 테스트의 이름이 실행과 어긋난다.

## 미커버 분기에 대한 판단

`B2@223`은 goroutine 안의 `Notify` 오류 경로다. 정상 실행에서 진입하지 않으며, 진입한다면
이 테스트가 아니라 프로덕션이 깨진 것이다. `not-applicable`: 실패 보고 경로.
