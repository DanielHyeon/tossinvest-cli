# Function Logic Map: `_verified_objects` (Python, a122 task 7.5.34 — 새 함수)

`ast.after-7.5.34.json` — 분기 **11** · raise 7 · 반환 2. `enumerate.py` 가 기계로 열거했다.

## 답하는 질문

실제 저장소가 oid 로 내놓은 바이트가 **정말 그 oid 의 객체인가.** git 은 객체를 oid 로 찾을 뿐 읽은 바이트를 해시하지
않는다 — 교체 참조 · 위조 loose · 위조 pack(git 은 pack 을 먼저 본다)이 다른 바이트를 그 이름으로 내놓는다. 7.5.31 은
git 밖에서 **있음**만 대조했다(재리뷰 #1 · #2). 이 함수는 `"<종류> <크기>\0" + 바이트` 를 Python 이 해시해 물은 oid 와
같아야 받는다.

## 갈래

| 분기 | 뜻 |

| B1 | 물을 것이 없으면 git 을 부르지 않는다(빈 dict) |

| B8 | 크기만큼의 몸과 끝 표시가 들어갈 자리가 없다 → 잘림 |

## 믿는 것

oid 는 호출자가 준다 — 검증한 커밋 · 트리에서 나왔거나(base · 커밋 대상), 실제 인덱스가 적은 oid 다(sparse 로 안
꺼낸 파일). 인덱스의 oid 자체는 믿는다: 그것이 "지금 판정하는 쪽의 이 파일" 의 정의다. 그 oid 의 **바이트**는 믿지 않는다.
