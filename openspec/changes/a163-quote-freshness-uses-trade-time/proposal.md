# a163 · 시세의 체결 시각을 버리지 않는다 — 기록하고 알리되, 손절을 미루지 않는다

> **High-risk.** 청산 관측 루프(`internal/app/engine/exitloop.go`)와 공식 시세 어댑터(`internal/official/market_reads.go`)를
> 건드린다(안전 부트스트랩 5 — 손절·청산 경로). 단, 이 change 는 **판정 자격을 하나도 바꾸지 않는다** — 그 경계가 이 change 의
> 핵심 계약이다(아래 「안전 불변식」). 사용자 방향 결정: **2026-10-21 「A」** (design D0).

## 왜

`/api/v1/prices` 응답에는 브로커의 `timestamp`(계약 이름 「데이터 시각」)가 실려 온다. 그런데 공식 어댑터 `adaptPrices` 는 그
필드를 디코드만 하고 버린 뒤 `FetchedAt = time.Now().UTC()` 를 채운다(AST: `analysis/ast/official--adaptprices.ast.json` — 분기 1 ·
시각 호출 `:175 time.Now` 하나 · `Timestamp` 읽기 0). 그래서 청산 루프의 시세 신선도 검사(`observe` B7 · `quoteUsable`, 15 s)는
「마지막 체결이 얼마나 오래됐나」가 아니라 「응답을 받은 지 얼마나 됐나」를 잰다.

결과는 측정돼 있다. a112 결정 46 의 사람 승인 프로브(2026-08-28 05:29 KST)에서 KR `/prices` 는 `2026-08-27T19:59:59.000+09:00`
— **9시간 30분 묵은** 시각 — 을 성공으로 돌려주었다(`analysis/quote-time-evidence.md` §2.2). 그런 값이 청산 루프에는 「15 s 안에 받은
신선한 관측」으로 보인다. 운영자도 그 사실을 볼 방법이 없다: 어떤 로그·알림·화면에도 체결 시각이 남지 않는다.

그렇다고 신선도 기준을 체결 시각으로 **바꾸면** 더 나쁘다. 청산 루프는 `quoteUsable` 이 거짓이면 그 포지션의 손절 비교를 건너뛴다
(`ObserveOnce` B7 `:511` `continue`, 나머지 다섯 호출자 `return nil`). 닫힌 시장·`timestamp` null(계약상 「체결 미발생」)·저유동 종목·
VI·거래정지 — 체결이 멈추는 구간마다 손절 판정이 사라지고, 그 구간이 바로 가격이 가장 크게 움직일 수 있는 구간이다
(`analysis/quote-time-evidence.md` §4). 이것은 안전 불변식 「손절·비상 청산의 즉시성을 약화·지연하지 않는다」 위반이다.

그래서 이 change 는 **보이게 만드는 것**까지만 한다: 체결 시각을 받은 시각 **옆에** 보존하고, 체결이 오래된 관측을 기록·알린다.
판정은 지금과 같은 받은 시각 기준으로 계속 돈다.

## 무엇을

1. **공식 시세 어댑터가 브로커 시각을 보존한다.** `domain.Quote` 에 브로커 데이터 시각 필드를 더하고 `adaptPrices` 가
   `timestamp` 를 해독해 채운다. null·키 없음·해독 실패는 **0 값(「모름」)** 으로 둔다 — 우리 시계로 메우지 않는다(a112 결정 35 와
   같은 이유). `FetchedAt` 은 **의미·값 모두 그대로**(받은 시각)다.
2. **청산 루프가 체결 나이를 기록한다.** 판정에 들어간 관측마다 체결 나이(`FetchedAt − 브로커 시각`, 브로커 시각이 0 이면 「모름」)를
   구조화 로그 필드로 남긴다.
3. **브로커 시각이 없는 관측을 알린다.** 한 주기의 **모든 포지션 판정이 끝난 뒤** 한 번, 브로커 시각이 「모름」인 포지션을
   `source_missing` 일반 등급 알림으로 올린다(H2·H4). 같은 포지션의 같은 사유는 래치로 한 번만 올린다.
4. 「체결이 오래됨」 알림은 **이 change 에서 내지 않는다**(H1). 나이는 로그 필드로만 남고, 배포 뒤 그 분포(H6)를 보고 임계·정규장 한정을
   별도 Story 에서 정한다.

  (`internal/app/engine/exit_source_age.go` 가안)에 둔다.

  원장 `ObservedAt`, journal schema 전부 그대로(사람 결정 H5 가 로그 전용을 고르는 경우).
- 공식 API 호출 수: 변화 0(같은 응답의 버려지던 필드를 읽을 뿐). rate budget 재계상 불요.
- `domain.Quote` 의 JSON 출력(`tossctl quote --json` 등)에 필드 하나가 늘어난다(`omitempty` 가안 — 사람 결정 H7).

  (사람 결정 H3).
- `officialbars.PollQuoteL1` 의 나이 상한(a112 잔여 (k)) — 생산 호출자 0, 배선하는 change 의 몫.
- a087 D7(장외 시간 보호 청산의 주문 유형) 처분. 이 change 는 그 위험을 키우지도 줄이지도 않는다.
- `adaptOrderbook` 의 시각 보존(생산 판정 소비자 0 — 사람 결정 H7 에서 포함 여부만 묻는다).
- 원장 schema 변경·콘솔 화면 변경(사람 결정 H5·H2 가 다르게 고르면 별도 Story).
- 장중 브로커 시각 동작의 실측(필요하면 사람 승인 읽기 전용 프로브 — 사람 결정 H6).
