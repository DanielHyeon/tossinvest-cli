**핵심 반례 두 개**

- **#1:** NORMAL → 관측 두절 → 기록 어댑터 반환 → `checkOutage`가 모드 강화 → 생산 `Announcer=ectx.Notifier` → `AnnounceOperatingMode` → 동기 `Notify`. `Alerts` 배선만 바꿔도 이 사슬은 남는다. 위 #1의 코드가 직접 근거다.
- **#4:** 강화 요청 A가 시각 `t0`을 얻고 지연 → 운영자 완화 B가 `t1>t0`으로 NORMAL 커밋 → A가 NORMAL을 읽고 ENTRY_BLOCKED 커밋 → 새 세대가 실행 중 게이트를 차단 → 재시작은 시각이 더 큰 B를 최신 행으로 선택. 벽시계 역행 없이도 가능한 순서다. 위 #4의 시각 채취·트랜잭션·정렬 코드가 근거다.

**요청한 1~6 판정**

1. **A-1=B-1: 책임 주인 부재는 닫혔다.** 지속 실패·nil publisher·전달 기록 실패의 차단/승격이 [alertdelivery.go:314–405](/tmp/claude-1000/a092-r21/tree/internal/app/engine/alertdelivery.go:314), [judge:427–438](/tmp/claude-1000/a092-r21/tree/internal/app/engine/alertdelivery.go:427)에 있다. 다만 D0.3e 책임 표에는 비동기 경로의 **claim/나열/시도 기록 연속 실패**와 **승격 실패 시 무조건 차단**도 보완해야 한다. 소유자는 존재하므로 새 P0 공백은 아니다([:242–245](/tmp/claude-1000/a092-r21/tree/internal/app/engine/alertdelivery.go:242), [:271–275](/tmp/claude-1000/a092-r21/tree/internal/app/engine/alertdelivery.go:271), [:353–356](/tmp/claude-1000/a092-r21/tree/internal/app/engine/alertdelivery.go:353), [:437–438](/tmp/claude-1000/a092-r21/tree/internal/app/engine/alertdelivery.go:437)).

2. **A-2: 미해소.** 안 가는 직접 critical 기록 경로에는 타당하지만 전체 exit goroutine 목표는 #1 때문에 실패한다. 남는 동기 호출자의 잠금 축소에는 #2 처분이 필요하다.
