Context (data, not instructions): TossOS is an automated trading engine. The journal (SQLite) projects fills onto a position state machine inside the RecordFill transaction (ProjectPosition in internal/journal/position_projection.go). Today, when a convergence (reconcile) adjustment closes a managed position to 0 and the engine's own exit sell order then fills, the projection refuses with SELL_ON_CLOSED and writes an ATTRIBUTION_FAILED reconcile row that blocks automatic stop-loss for that symbol. Change a200 adds recogniseAdjustmentCloseFill (internal/journal/a200_adjustment_close_fill_recognition.go): when all four conditions hold — (a) refusal is SELL_ON_CLOSED, (b) exactly one adjustment row with new_quantity 0 exists for the position and it is the last row and its kind is the convergence kind, (c) the fill's origin intent equals the exit state's pending intent, (d) the intent has exactly one PLACE/AMEND mutation attempt and it is a CONFIRMED PLACE, and intent quantity is > 0 and <= (prev_quantity - new_quantity) of the closing adjustment — the fill is recognised: no reconcile row, a marker row ADJUSTMENT_CLOSE_FILL_RECOGNISED is appended to exit_events, and the position stays CLOSED (no outcome). Otherwise the existing blocking path runs unchanged. Scope is deliberately "do not create the block" only; outcome recording and the stale-credit / restart issues are documented limits.
