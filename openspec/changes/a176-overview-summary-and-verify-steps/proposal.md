# a176 — 개요 한 화면 요약 정돈 · `/verify` 단계 목록 구조화 (정의, 미착수)

프로그램 맥락: `openspec/changes/a173-console-ux-common-cleanup/proposal.md` 「프로그램 개요」 S4. 착수 조건: a173 착지 뒤.

## Why
2026-10-25 실측: `/dashboard` 4507px·851 단어. 요약 카드 행이 아래 섹션과 중복, "구조적으로 미측정 — …" 문단이 같은 글로 3회, 검증 기록 절대경로 본문 노출. `/verify` 는 단계 목록이 5188px 고정폭 CLI 텍스트(`tossctl verify run --list` 출력 그대로).

## 스펙 제약
`operator-console` 704~718(개요 요약: 세로 스크롤 없이·칸마다 사실 1 + 상세 링크·재계산 금지·**기존 상세 섹션 제거 금지**), 1372~1390(여섯 사실·시장별 분리·미측정 여덟 사유·브로커 호출 0·확인 마찰 0), 1326·1344~1370(검증 화면: 시장 선택·단계 목록·승인 채널 기록 유지).

## What Changes
1. 개요: 요약 영역을 "엔진·보호 / 오늘 손익·한도 소진 / 예외" 세 묶음으로 정돈(여섯 사실은 모두 포함), 같은 설명 1회, Guardian 한도 표는 값 + 설정 링크, 검증 기록 경로는 접힌 기술 정보. 상세 섹션은 그대로 둔다.
2. `/verify`: 단계 목록을 단계별 `<details>`(제목·`mutating` 배지·요약)로 렌더. 전체 텍스트는 DOM 에 남긴다(`--list` 와 같은 내용). 시작·승인·중단 폼과 CSRF·확인 문자열 절차는 변경 0.

## Scope / Non-goals
- 범위: `templates_overview.go`·verify 템플릿(`templates.go`)·CSS·시험.
- 비목표: 승인 절차·확인 문자열·폼·브로커 호출·새 상수·상세 섹션 삭제.

## Risk
Low~Medium. `/verify` 는 승인 창이 있는 화면이라 폼 마크업은 건드리지 않고 목록만 구조화한다. 렌더 비교 시험으로 폼 전후 동일 단언.

## 완료 기준
Story acceptance(`STORY-TOS-a176`): 개요 요약 1280 ≤ 900px, 설명 중복 0, `/verify` 폼 바이트 동일.

## not-applicable
변이 원장·다중 적대 리뷰: 비례 원칙(읽기 전용 렌더, `/verify` 폼은 바이트 불변). FLM/BTM 은 면제를 미리 주장하지 않는다: 기존 Go 함수 본문(시험 함수 포함)을 고치면 gate ⑤ 가 함수마다 번들을 요구한다. 새 파일·새 메서드를 우선한다.

Manager 착수 전 정정(2026-10-27): design §1·§2.2 ★ — 단계 데이터는 `WriteSteps` 문자열이라 verifylive 를 편집하지 않고 알려진 ID 경계에서 무손실 분할(이으면 원문과 바이트 동일, 실패 시 종전 `<pre>`), 개요 요약 `dl.console-summary` 와 구조적 미측정 1회 처리는 a173 이 이미 넣었음.
