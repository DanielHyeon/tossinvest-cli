- [x] 2.2 v7 → v8 additive 마이그레이션. **하향 마이그레이션을 만들지 않는다** — `schema.go`의 계약대로 롤백은 이전 바이너리 실행(`ErrSchemaTooNew` 거부)이고 중간 실패 복구는 자동 사전 백업(`backup.go`)이다. 그 두 경로가 v8에서 동작함을 테스트(구 바이너리 거부 + 백업 생성)
- [x] 2.3 `RiskIntent.Canonical()`과 `risk_hash`가 바이트 단위로 불변임을 골든 테스트로 고정 — 이 change가 결정 계약을 건드리지 않았다는 증거
- [x] 2.4 **결정 참조가 외래키가 아님**을 테스트로 고정: 결정 행이 만료·정리되어도 관측 행이 남고 정리가 막히지 않는다(`spent_nonces` 선례와 동일 근거)
- [x] 2.5 **결손 탐지·부분 재구성**: 관측 없는 발급 결정을 계약 테이블 안티조인으로 찾는다. 복원되는 항목(가격 3개·시장·계좌·심볼·수량·정책 버전은 preimage에서, 발급 시각은 `decisions.issued_at`에서, 결과 구분은 `ALLOWED_ISSUED`)과 **복원되지 않는 항목**(순 RR·실질본전·비용모델 지문 — 당시 요율 지문이 preimage에 없어 원리적으로 불가)을 테스트로 구분 고정. 재구성 행은 재구성 표지 + **발급 시각·재구성 시각 둘 다** + 재구성 시점 지문을 담고 원본과 구별 가능해야 함. 목표가 복원이 최소 RR rung의 거부에 의존함(preimage 계약은 목표가를 선택 항목으로 둔다)을 주석·테스트로 명시
- [x] 2.5b **재구성 배치 제약**(라운드 3 CRITICAL): 탐지·재구성 작업을 **엔진 런타임의 `SupervisedLoop`으로 등록하지 않는다**. 감독 루프의 반환은 전 루프 종료이므로 측정 오류가 exit observer·filldetect를 함께 죽이고(§0.3), 연속 실패 임계는 ENTRY_BLOCKED로 이어지며, 트리거가 폐쇄 열거라 대사 실패 트리거를 차용해 원인을 오귀속한다. 별개 프로세스·스케줄 경계에서 수행되고 어떤 `ModeTrigger`에도 사상되지 않음을 구조 테스트로 고정
- [x] 2.5c **중복 재구성 방지**(라운드 3 HIGH): 재구성은 **관측 쓰기 데드라인 초과 결정에만** 적용. 진행 중 쓰기를 결손으로 오인해 재구성하면 실제 쓰기가 뒤이어 착지해 한 결정에 두 행이 남고 분포가 이중 계수된다. 발급 판정의 결정 참조에 **유일 인덱스**(외래키 아님)를 두고, 경합 주입 테스트로 단일 행을 단언
- [x] 2.5d **정리 지평 경계**(라운드 3): 탐지·재구성 주기가 결정 행 정리 지평보다 짧음을 계약으로 고정. 재구성 전에 정리되어 영구 손실이 된 건수를 계수(결정이 사라지면 결손은 탐지도 복원도 불가)
- [x] 2.6 보존 기간 정책(trade-analytics 180일 기준과 정합) + 정리가 주문 경로 트랜잭션과 경쟁하지 않는 비동기 작업임을 테스트
- [x] 2.7 기록 API: 실패가 호출자의 판정 결과를 바꾸지 않음을 테스트
- [x] 2.8 **열화 계수를 관측 행과 독립된 실패영역에 기록**(라운드 3 P0): 관측 테이블에 열화 행을 쓰는 설계는 자기모순이다 — 디스크 소진·I/O 오류로 관측 INSERT가 실패하면 같은 저장소의 열화 쓰기도 실패한다. `SQLITE_FULL` 주입 테스트로 독립성을 증명하고, 독립 저장마저 불가한 경우 구조화 로그 + 프로세스 내 단조 카운터로 강등되며 거래 경로가 계속됨을 테스트. **그 강등 계수를 재시작 후 durable하다고 주장하지 않음**을 문서·테스트로 명시

- [x] 3.6 정밀도 한계 테스트: 요율 전부 0인 configured 모델에서 순 RR == 총 RR(등호), 고정밀 진입가에서 `B < entry`가 되어 순 > 총이 되는 입력 — **관측값에서는 결함이 아니라 기록해야 할 사실**임을 테스트 이름과 주석으로 명시. 게이트 승격 change가 이 테스트를 반드시 보게 된다

## 4. execgw + obs — 기록 배선 (거부 경로의 첫 영속)

- [x] 4.1 체인 판정 직후 관측을 기록. **원자 트랜잭션 밖**(커밋 이후)에 두어 관측 실패가 결정·예약을 롤백하지 않음을 테스트. 거부(`chainRefusal` 경로 — 현재 영속 없음)와 ALLOW 양쪽
- [x] 4.1b **관측이 제출을 막지 않음**(라운드 3 P1): 관측 기록은 Gateway 제출의 선행조건도 동기 대기 지점도 아니어야 한다. 관측 쓰기를 인위적으로 지연시켜도 제출과 HELD 예약 검증이 지연·취소되지 않고 결정 TTL(60초)이 소진되지 않음을 테스트
- [x] 4.2 **결과 구분이 정확히 기록됨**을 테스트: 체인 ALLOW 후 발급이 `LIMIT_REACHED`·`DECISION_EXPIRED`·`VERSION_CONFLICT`·`SNAPSHOT_RECOLLECTION_EXHAUSTED`로 거부되면 `ALLOWED_ISSUANCE_REFUSED` + 그 코드가 남고 거부 판정으로 오기록되지 않음
- [x] 4.3 **진입 한정** 범위 고정: `IssueReduction`이 공유하는 `evaluateChain` seam에는 배선하지 않는다(stop·target이 없어 전 항목 결측 행만 생성). `Evaluate` 내부에도 배선 금지 — 순수 체인에 journal 의존이 생기면 5.4의 하네스 격리가 깨진다
- [x] 4.4 비용모델 지문 산출 — 요율 집합에서 결정론적으로 유도되고 요율이 바뀌면 반드시 바뀜을 테스트
- [x] 4.5 비용 범위를 `FEE_TAX_ONLY`로 기록. 슬리피지 미포함이 기록 자체로 식별됨을 테스트
- [x] 4.6 **`internal/obs` 이벤트 타입 추가 — 등급은 `SeverityNormal`**(라운드 2 R2-13 + 라운드 3 F7): 관측 실패 알림용. `obs.Severity`에는 `critical`과 `normal`만 있으므로 "비강화 등급"이라는 제3의 등급을 만들지 않는다. **`criticalEvents` 등급표의 비구성원성을 단언하는 테스트를 신설** — 기존 표 테스트는 포함만 단언하므로 누락되면 v8 열 오타가 `Gate.Block` + ENTRY_BLOCKED로 번지는 유일한 구조적 스위치가 열린다
- [x] 4.7 **강화 배제 e2e 테스트**(라운드 2 P0): 관측 쓰기 실패 + 그 알림 전달 소진 후에도 운영 모드·`EntryGate`가 불변임을 관통 테스트. `outbox` critical 경로·`CRITICAL_ALERT_UNDELIVERED`·`Gate.Block`에 도달하지 않음을 단언

## 5. 반사실 측정 하네스
