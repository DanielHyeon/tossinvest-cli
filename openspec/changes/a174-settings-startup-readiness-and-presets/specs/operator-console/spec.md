## ADDED Requirements

### Requirement: 기동 준비는 읽기 전용 체크리스트 하나로 읽힌다

콘솔은 엔진 기동 인터록이 보는 조건(자동화 게이트·엔진 자동 시작·Guardian 한도 다섯과 통화·거래 정책 넷)의 현재 상태를 **읽기 전용 체크리스트 하나**로 렌더해야 한다(SHALL). 체크리스트는 설정 상시·당일 하위 화면의 머리와 검증 콘솔의 엔진 시작·정지 컨트롤 바로 위에 같은 내용으로 나타나고(SHALL), 각 줄은 그 컨트롤을 소유한 화면으로 가는 링크를 갖는다(SHALL). 체크리스트는 컨트롤을 복제하지 않으며(SHALL NOT — 「설정은 가역성과 빈도로 분류된다」의 단일 위치 규칙), 기동 인터록이 이미 계산한 판정을 옮길 뿐 재계산하지 않는다(SHALL NOT).

#### Scenario: 상시 탭에서 게이트를 켜기 전
- **WHEN** 상시 하위 화면을 열면
- **THEN** 머리의 체크리스트가 한도 미설정과 거래 정책 꺼짐을 소유 탭 링크와 함께 보여 주고, 같은 판정을 다시 그리는 표(기존 「기동 인터록 사전 판정」 표)는 본문에 없다. 저장 버튼 옆의 결과 안내(누르면 기동이 거부된다는 문장)는 그 버튼의 결과로 남는다

#### Scenario: 검증 콘솔의 엔진 시작 위
- **WHEN** 검증 콘솔을 열면
- **THEN** 엔진 시작·정지 컨트롤은 이동 전과 같이 존재하고 그 바로 위에 같은 체크리스트가 읽기 전용으로 있다

### Requirement: Guardian 프리셋은 비교표 하나로 고른다

Guardian 한도 프리셋은 통화(KR/US)별 비교표 하나로 렌더해야 한다(SHALL): 행은 한도 항목, 열은 현재 값과 각 프리셋, 열마다 기존 프리셋 적용 폼 하나. 통화 환산 설명은 통화당 1회다(SHALL). 개별 값 입력 폼은 접힌 고급으로 남는다(SHALL). 제출 경로·필드명·CSRF·audit 는 바뀌지 않는다(SHALL NOT).

#### Scenario: 프리셋 비교
- **WHEN** 당일 하위 화면의 Guardian 한도를 보면
- **THEN** 현재 값과 프리셋 값이 같은 표의 이웃 열에 있고, 프리셋마다 적용 버튼이 하나다

### Requirement: 거래 정책 토글은 한 줄에 한 번 나타난다

거래 정책 네 토글은 각각 체크박스·라벨·현재 상태 배지·한 줄 설명이 한 블록에 있는 줄로 1회만 렌더해야 한다(SHALL). 설명은 자기 체크박스의 블록 안에 있어 다음 토글에 붙어 보이지 않는다(SHALL NOT). 확인 문구나 추가 확인 단계는 두지 않는다(SHALL NOT).

#### Scenario: 매도 토글의 설명
- **WHEN** 거래 정책 폼을 렌더하면
- **THEN** "주문 제출" 의 설명은 "주문 제출" 체크박스와 같은 블록 안에 있고 "매도" 줄에는 "매도" 의 설명만 있다
