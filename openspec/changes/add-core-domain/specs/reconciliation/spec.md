# reconciliation Specification (delta)

## MODIFIED Requirements

### Requirement: Reconciliation 계약
재시작·주기 reconciliation은 명세된 계약을 따라야 한다(SHALL): 비교 키(계좌·심볼·시장), 수량·평균단가 허용 오차, 안정화 시간, 외부 수동 주문의 별도 provenance 분류, 충돌 시 브로커 계좌가 최종 권위. 로컬 상태의 출처는 **Position 투영**이다(SHALL — 체결 이벤트+조정 이벤트의 투영; 기존 fills-only 파생과 별도의 두 번째 계산을 두지 않는다). 불일치는 조정 이벤트 발행으로 수렴시키며(SHALL — position-ledger), 투영을 직접 덮어쓰지 않는다(SHALL NOT).

#### Scenario: 수량 불일치 수렴
- **WHEN** 브로커 보유수량이 로컬 투영과 다르면
- **THEN** 조정 이벤트가 발행되어 투영이 계좌 값으로 수렴하고, 이후 재조회에서 일치가 확인된다

#### Scenario: 조정 후 로컬 상태 일치
- **WHEN** 조정 이벤트 반영 후 reconciliation이 다시 수행되면
- **THEN** 로컬 상태(투영)와 계좌가 일치해 불일치가 보고되지 않는다

### Requirement: 불일치 시 진입 차단
수량·평균단가 불일치가 감지되면 신규 진입은 차단되어야 한다(SHALL — RECONCILE 상태, order-execution 메인 스펙). 차단 해제는 다음 중 하나다(SHALL): (a) 조정 이벤트 반영 후 재조회 일치(자동 — 원인 기록 필수), (b) 연속 실패 임계(기본 3회) 도달 시 영구 차단으로 승격되어 운영자 확인으로만 해제. 자동 해제는 조정이 반영된 재조회 일치에만 근거하며, 조정 없이 우연히 일치한 단발 관측으로 영구 차단을 풀어서는 안 된다(SHALL NOT). 청산·보호 경로는 차단의 대상이 아니며 확정 하한 규칙을 따른다(§0.3).

#### Scenario: 조정 반영 후 자동 해제
- **WHEN** 조정 이벤트가 반영되고 재조회가 일치하면
- **THEN** 진입 차단이 원인 기록과 함께 자동 해제된다

#### Scenario: 영구 차단의 운영자 해제
- **WHEN** 연속 실패 임계를 넘어 영구 차단으로 승격된 뒤 재조회가 일치하면
- **THEN** 자동 해제되지 않고 운영자 확인을 요구한다
