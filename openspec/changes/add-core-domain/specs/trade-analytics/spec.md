# trade-analytics Specification (delta)

## ADDED Requirements

### Requirement: 거래 비용 모델
KRW·USD 거래의 수수료·거래세·환전 비용은 순수 함수 비용 모델로 계산되어야 하며(SHALL), 수치는 provenance 주석(StockOS 유래·Toss 검증 상태)과 함께 설정 주입으로 교체 가능해야 한다. Guardian의 현금·비용 검증과 성과 지표의 비용 차감이 같은 모델을 사용한다(SHALL — 이중 정의 금지). Toss 실측 검증 전에는 비용을 과대 추정한다(SHALL — 과소 추정은 진입 판정과 성과 지표를 동시에 낙관적으로 만든다).

#### Scenario: 왕복 비용 계산
- **WHEN** KR 매수·매도 왕복 비용을 계산하면
- **THEN** 수수료(bps)·거래세(bps)가 반영된 결정적 값이 반환되고 이식된 테스트 케이스와 일치한다

#### Scenario: 미검증 비용의 보수적 적용
- **WHEN** 검증되지 않은 비용 수치로 진입 판정을 수행하면
- **THEN** 과대 추정된 비용이 사용되어 판정이 보수적으로 기운다

### Requirement: 성과 원시 지표
거래 완결(청산) 시 다음 지표가 journal에 기록되어야 한다(SHALL): 비용 차감 후 실현손익, R 배수(실현손익 / 초기 위험), 보유 시간. 집계 지표(승률·profit factor·MDD)는 원시 기록에서 파생 계산한다(SHALL — 원시 데이터가 권위). MFE/MAE는 보유 기간의 시장가 관측을 요구하는데 그 데이터 소스가 아직 없으므로 이 change의 범위가 아니다(SHALL NOT — 시세 스트림 도입 시 추가).

#### Scenario: 청산 완결 시 기록
- **WHEN** 포지션이 CLOSED로 전이하면
- **THEN** 비용 차감 실현손익·R 배수·보유 시간이 provenance와 연결되어 기록된다

### Requirement: 분석 경로의 격리
성과 지표의 계산·집계와 보존 기간 정리는 주문 실행 경로에서 격리되어야 한다(SHALL). 포지션 종결 트랜잭션은 종결 사실만 원자적으로 기록하고, 지표 계산·집계·삭제는 durable outbox 기반 비동기 작업으로 수행한다(SHALL). 분석 작업의 실패나 지연이 체결 반영·보호주문 처리를 지연시키거나 실행 상태를 되돌려서는 안 된다(SHALL NOT). 성과·관측 테이블은 보존 기간 정책(기본 180일)을 갖는다(SHALL).

#### Scenario: 분석 계산 실패
- **WHEN** 성과 지표 계산이 실패하면
- **THEN** 포지션 종결과 보호주문 정리는 정상 완료되고 분석 작업만 재시도 대상으로 남는다

#### Scenario: 보존 기간 정리
- **WHEN** 180일이 지난 성과 기록의 정리가 수행되면
- **THEN** 주문 경로의 DB 트랜잭션과 경쟁하지 않는 비동기 작업으로 처리된다
