## Context

대시보드와 포지션 화면의 보유종목 정보가 서로 다른 깊이와 정책 문맥을 보여 주고,
핵심 가격·손익보다 원장 근거와 식별자가 앞에 나와 빠르게 읽기 어려웠다.

## Observation

두 화면이 같은 종목을 다르게 설명하지 않으려면 handler별 template 정리가 아니라
설정·실행 상태·lifecycle·exit evidence를 붙이는 request-local projection부터
공유해야 한다. 핵심 행은 종목, 수량, 평단, 현재가, 다섯 보호 라인, 총금액,
미실현 손익만 유지하고 원시 원장값·정책·식별자는 native disclosure로 내린다.

반응형 table을 card grid로 바꿀 때 `::before` 라벨만 추가하면 여러 직접 자식이
두 열에 자동 배치될 수 있다. 라벨을 첫 열, 모든 직접 콘텐츠를 둘째 열로 고정하고
내부 line grid는 독립적으로 유지해야 한다. CSS 문자열 검사만으로는 부족하므로
실제 375 CSS px 브라우저에서 `scrollWidth`, 행별 line 개수, disclosure 열림을
확인한다.

## Evidence

KR/US shared projection, canonical/unknown/raw evidence 경계, broker-only 설명,
masked account disclosure, input-free/accessibility/mobile CSS 계약을 RED/GREEN으로
고정했다. 독립 보안·유지보수·UI 리뷰에서 발견된 P1을 모두 수정했고 focused,
race, 전체 Go test, vet, strict OpenSpec, SDD와 8단계 gate가 통과했다.
배포된 Chromium 1440 px와 375 px의 두 화면은 viewport overflow 없이 7개 열,
종목별 5개 line, 입력 0개, 정상 disclosure를 보였다.

## What to reuse

동일한 운영 사실을 여러 화면에 보여 줄 때는 view model enrichment와 template을
함께 공유한다. primary에는 지금 행동 판단에 필요한 canonical 사실과 fail-closed
사유를 두고, provenance·raw evidence·identity는 명시적으로 비실효임을 표시한
disclosure에 둔다. 모바일 card 변환은 실제 브라우저 치수를 배포 canary로 잰다.

## What not to infer

이 학습은 raw 저장값을 현재 손절·익절 기준으로 승격하지 않으며, 브로커 refresh,
설정 저장, 엔진 토글, 자동 시작 또는 LIVE 주문 권한을 추가하지 않는다.
