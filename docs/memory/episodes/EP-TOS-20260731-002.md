## Context

기존 콘솔은 `127.0.0.1`과 터미널에 출력된 URL token 점유를 인증으로 사용했다.
모바일 VPN에서 조회뿐 아니라 설정·엔진 제어·검증 기능을 쓰려면 단순 port publish가
이 장기 URL credential을 원격으로 노출하고, VPN 또는 Docker NAT 하나를 전체 신뢰
경계로 오인할 위험이 있었다.

## Observation

기본 local mode는 그대로 두고 remote mode를 all-or-nothing으로 분리해야 한다.
호스트의 VPN IP publish, 실제 socket bind, peer CIDR, canonical HTTPS Host/Origin,
URL에 없는 고엔트로피 login token, IP/UA-bound idle/absolute session, 기존 CSRF,
append-only access audit가 각각 독립적으로 실패해야 한다. Docker 내부 wildcard는
host publish와 application peer 검사가 함께 있을 때만 허용할 수 있다.

## Evidence

remote 구성·TLS hostname·bind·CIDR·Host/Origin/Referer·session·logout·handoff·
rate/audit의 RED/GREEN 테스트와 race 검사를 통과했다. Compose missing-variable 및
render 검증, non-root multi-stage image build/inspect, 더미 TLS health/login smoke를
실행했다. Smoke에서 `0.0.0.0`이 `::` dual-stack listener로 승격되는 문제와 host
0600 credential-file UID 불일치를 발견해 각각 명시적 `tcp4`/`tcp6`와 required non-root
host UID/GID로 고쳤다.

## What to reuse

loopback possession 인증을 원격으로 확장하지 말고 별도 원격 인증 mode를 만든다.
wildcard bind가 필요하면 address family를 고정하고 실제 listener 주소를 다시
검증한다. Compose credential file은 mode만 보지 말고 runtime UID가 실제로 읽을 수
있는지 smoke test한다. 로그인 실패 audit와 in-memory session/attempt state도
공격자가 늘릴 수 있는 자원이므로 window당 기록과 총량을 함께 제한한다.

## What not to infer

VPN 연결이 곧 인증이라는 뜻이 아니며, 이 구성은 인터넷 공개·reverse proxy
신뢰·다중 사용자 RBAC를 승인하지 않는다. 원격 session은 기존 콘솔 기능만 열며
LIVE 주문 자동 승인, 엔진 기동 승인 또는 automation gate 변경 승인을 새로
부여하지 않는다.
