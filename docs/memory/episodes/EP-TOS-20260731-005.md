## Context

콘솔의 soak 재시작을 한 번의 조작으로 만들면서, 기존 자격 세대의 유효한 캐시가
새로 제출된 자격 검증이나 새 프로세스 기동에 섞일 수 있는 경합을 다뤘다.

## Observation

교체 자격은 기존 캐시와 분리된 임시 저장소로 조회 검증해야 한다. 기존 soak이
종료되기 전에 공용 캐시만 지우면 종료 중인 프로세스가 이를 다시 만들 수 있으므로,
종료 확인 뒤 새 프로세스 생성 직전에 캐시를 다시 폐기하는 장벽이 필요하다.
파일 세대 교체 중 실패는 지속적인 pending marker로 표시하고, 자격 파일은 같은
디렉터리의 임시 일반 파일을 원자 교체한 뒤 0600 권한을 검증해야 한다.

## Evidence

누락·거부·환경 관리·일시 오류·동시 요청·저장 실패·기존 프로세스 경합을 분기
테스트로 고정했다. focused, race, 전체 Go test, vet, strict OpenSpec, PM 1:1,
독립 보안 리뷰와 8단계 gate가 통과했다. 배포 이미지의 격리 컨테이너에서는 누락
상태가 설정 화면으로 이동하고 파일이나 soak 로그를 만들지 않음을 확인했다.

## What to reuse

운영 자격 세대를 바꾸고 프로세스를 재기동하는 흐름은 단일 mutex 아래에서
격리 검증, pending marker, 원자 저장, 감사 기록, 기존 프로세스 종료 확인,
pre-spawn 캐시 폐기를 순서대로 수행한다. 어느 단계든 실패하면 새 프로세스를
만들지 않고 고정된 오류 분류만 반환한다.

## What not to infer

이 흐름은 실제 주문 승인, 엔진 운영 토글 승인, 인터넷 공개 또는 VPN 바깥 접근을
허용하지 않는다. 배포 검증도 실제 Open API 호출이나 soak·엔진 기동을 의미하지
않는다.
