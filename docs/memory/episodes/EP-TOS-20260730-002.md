## Context

기존 설정 화면은 이미 준비된 `<tossctl>.candidate`를 검토·설치할 수 있었지만,
운영자가 매 릴리스마다 개발 checkout에서 후보를 직접 만들어야 했다.

## Observation

전송 checksum만 확인하는 updater에 메뉴만 추가하면 원격 실행 경로가 된다. 공식
release archive의 완전한 Sigstore 검증, 정확한 workflow·tag·source commit,
안전한 USTAR 추출, 추출된 Go binary의 VCS revision, 원자적 고정 sibling 게시를
연속된 fail-closed 사슬로 검증해야 한다. 다운로드와 설치도 같은 요청에서 수행하면
사람의 최종 검토 경계가 사라진다.

## Evidence

고정 latest release 및 host allowlist, Fulcio·Rekor·SLSA policy, PAX·GNU·sparse·
multistream·경로 공격 거부, 기존 candidate 복구, stage·inspect·install 직렬화,
세션·CSRF, 두 태그 다운로드 single-flight, 실제 CLI 조립을 회귀 테스트했다.
집중 race 테스트와 저장소 전체 Go 테스트, vet, strict OpenSpec 검증,
CodeGraph fingerprint와 SDD check가 통과했다.

## What to reuse

자체 업데이트 기능은 `discover and verify → fixed candidate stage → human review →
separate install`의 네 경계로 나눈다. release workflow도 verifier의 신뢰 경계이므로
action SHA, 최소 권한, 최종 archive attestation, 기존 release 불변성을 함께
회귀 테스트한다.

## What not to infer

서명 검증된 candidate가 만들어졌다고 설치·재기동·engine 정지·gate 변경 또는
계좌 접근이 승인됐다고 추론하지 않는다. 콘솔 재시작 후 남은 candidate는
process-local provenance 영수증이 없으므로 출처 확인 상태로 표시하지 않는다.
