## Context

외부 종목 자동관리 화면의 합성 손절폭 표시가 inline handler 차단 때문에 5%에
고정되어 보였고, 콘솔이 엔진과 다른 journal을 선택해 관리 상태 조회가 구버전
`policy_id` 오류로 실패할 수 있었다.

## Observation

deny-by-default CSP에서 inline 동작에 의존하는 range/output 조합은 실제 제출값과
표시값을 다르게 만들 수 있다. 보호 설정은 사람이 읽는 percentage를 숫자 입력으로
제출하고 서버가 유한성·범위·정확한 단위를 검증한 뒤 기존 fraction으로 변환해야
한다. 기존 off-grid 값의 경고 판단도 저장 parser를 재사용해야 표시와 저장 계약이
갈라지지 않는다.

콘솔의 read-only journal 경로는 별도 편의 경로가 아니라 엔진의 explicit
`configDir` 규칙을 그대로 따라야 한다. 선택된 journal이 없거나 구버전이면 다른
journal로 fallback하지 않고, 필요한 column을 query 전에 검사해 typed failure로
분류해야 한다.

## Evidence

실제 임시 journal 두 개를 사용한 profile identity/no-fallback 테스트, 원격 CSP
응답 테스트, 인증된 HTTP 설정 저장을 통한 `7.5 → 0.075` 왕복 테스트와 v8
pre-query 분류 테스트를 추가했다. focused·affected race·전체 Go test, vet,
strict OpenSpec, PM 1:1, 독립 구현 리뷰와 8단계 gate가 통과했다.

## What to reuse

CSP가 스크립트를 허용하지 않는 운영 화면의 보호 수치는 값과 단위를 입력 필드에
직접 드러내고 exact server parser를 표시 보정에도 재사용한다. 프로필별 durable
state를 읽는 보조 UI는 writer와 같은 path resolver를 공유하거나 그 규칙을
계약 테스트로 고정하며, 선택 실패를 다른 저장소 fallback으로 숨기지 않는다.

## What not to infer

이 학습은 손절 계산식, 기존 포지션의 보호선, 엔진 재시작, 운영 토글 또는 LIVE
주문 권한을 변경하지 않는다. 이미지 빌드 성공도 운영 컨테이너 재생성 승인을
의미하지 않는다.
