## Context

운영 설정에서 자동화 게이트와 USD 위험 한도를 활성화했지만 CLI 엔진 조립 경로가
Guardian을 주입하지 않아 시작 인터록이 모든 루프를 거절했다.

## Observation

설정 파싱이나 인터록 단위 테스트만으로는 운영 조립 누락을 잡지 못한다. Guardian은
실제 account 확인과 journal open 이후 만들어야 하고, 시작 인터록·engine context·exit
observer가 같은 인스턴스와 같은 journal을 사용해야 한다.

## Evidence

격리된 config와 공식 API `httptest` 서버, 실제 SQLite journal을 사용하는
`tossos_testseams` 태그 CLI 조립 회귀 테스트에서 Guardian 구성 횟수 1회, 설정된 USD
한도, reduce-only 결정의 context journal 가시성, exit observer 조립, context close 후
공유 journal 종료를 검증했다. 영향 패키지 race 테스트와 기존 journal crash suite도
통과했다.

## What to reuse

운영 권한 객체를 추가할 때는 설정값 존재가 아니라 실제 production assembler를
테스트하고, 권한 객체의 구성 횟수·소유 journal·모든 소비자의 인스턴스 동일성을 함께
검증한다.

## What not to infer

자동화 게이트 ON만으로 LIVE 주문이 승인된다고 추론하지 않는다. Gateway의 보호 배선,
Guardian 결정, 공식 주문 경로, 사람 승인 불변식은 각각 독립적으로 유지된다.
