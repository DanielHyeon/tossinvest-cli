## Context

TossOS에 StockOS의 공통 익절·보호선 정책 세 가지와 운영자 선택 화면을
이식했다. 공통값 변경이 기존 포지션의 청산 의미를 소급 변경하거나, 외부에서
매수한 포지션에 엔진 진입 포지션과 같은 부분익절을 자동 적용하면 운영자가
승인한 위험 경계가 흐려질 수 있었다.

## Observation

공통 설정은 계산 시점마다 읽는 동적 기본값이 아니라 포지션 관리 시작 시점에
정책 ID로 동결해야 한다. 외부 매수 포지션도 편입 시 정책 ID를 저장하되,
RUNNER의 자동 부분익절은 제거하고 보호선 침범 시 전량 위험 축소만 유지하는
출처별 변형이 필요하다. 고점 추종 보호선은 이전 보호선과 고정 바닥의 최댓값으로
합성해야 단조 불변식을 보존한다.

## Evidence

정책 레지스트리·정확한 분수 부분익절·runner 고점 보호선, v9 nullable 정책
스냅샷 migration, 신규/외부 편입 및 재기동 복구, session+CSRF 설정 화면을
각각 테스트했다. 영향을 받은 패키지의 race 검사, 전체 `make test`, `make vet`,
strict OpenSpec validation, Function Logic Map 검사와 독립 리뷰를 통과했다.
리뷰에서 runner 비율 parse 오류를 버리던 경로를 fail-closed로 고쳤고, v8
migration 검사가 최신 v9를 우연히 포함하지 않도록 경계를 분리했다.

## What to reuse

위험 정책의 공통 기본값은 새 상태를 만드는 순간 불변 ID로 스냅샷하고, 복구는
항상 저장된 ID를 우선한다. 동일 정책 이름이라도 포지션 provenance가 다르면
정책 수치 원본을 복제하기보다 명시적인 보수적 실행 변형을 resolver에서 만든다.
trailing floor는 기존 floor와 max-compose하고 파싱·정책 조회 오류는 실행 평가에서
다시 fail-closed로 전파한다.

## What not to infer

세 정책의 수익성이 보장되었다는 뜻이 아니며 기존 포지션을 자동 전환해도 된다는
승인도 아니다. Optimization 저장 권한은 LIVE 거래 권한, 주문 승인, 엔진 기동
승인 또는 원격 콘솔 노출 승인을 포함하지 않는다.
