## Context

대시보드와 포지션의 보유종목 표가 StockOS보다 성기고, 현재가와 보호 라인 사이가
멀었으며, 상세 disclosure가 미실현 PnL 열 안에서 행을 늘려 header와 값의 축을
흐트러뜨렸다.

## Observation

핵심 일곱 값의 순서를 유지하면서 마지막에 좁은 `상세` action 열을 명시하면
header/body 정렬을 보존할 수 있다. 상세 내용은 JavaScript나 입력 control 없이
native `details`를 fixed 중앙 surface로 표시하고, 열림 상태에서도 원래 행 높이를
바꾸지 않아야 한다. popup은 고정 높이보다 내용 크기를 따르되 viewport 안에서만
스크롤되게 해야 짧은 내용의 빈 공간과 긴 내용의 잘림을 함께 피할 수 있다.

CSS는 holdings 전용 `.detail-cell` 아래로 scope해야 같은 native disclosure를 쓰는
주문 화면에 누출되지 않는다. non-modal surface에 dim backdrop을 흉내 내면서 배경
클릭을 허용하면 사용자가 modal로 오인할 수 있으므로 backdrop 없이 계약을 분명히
한다.

## Evidence

공유 holdings template의 정확한 여덟 열, 마지막 상세 열, compact spacing,
행 높이 불변, 44 CSS px summary, 375 CSS px popup 내부 스크롤과 orders selector
격리를 RED/GREEN 테스트로 고정했다. 독립 보안·테스트·UX 리뷰에서 P1을 모두
수정했고 focused/race/전체 Go test, vet, strict OpenSpec, SDD와 full gate가
통과했다. 배포된 `/positions`와 `/dashboard`를 desktop/mobile Chromium에서
확인해 중앙 정렬, 수평 overflow 없음, 입력과 script 0개, console error 0개를
측정했다.

## What to reuse

운영 표의 긴 read-only 진단은 핵심 숫자 셀에 넣지 말고 마지막 전용 action 열로
분리한다. popup은 content-sized + viewport max-height 조합으로 만들고, 영향을
shared template에 한정하며 다른 disclosure consumer에 대한 selector leakage를
회귀 테스트한다.

## What not to infer

이 학습은 정책 계산, KR/US 편입 자격, 손절·익절 값, 엔진 토글, 설정 저장,
자동 시작 또는 LIVE 주문 권한을 변경하지 않는다. non-modal popup은 여러 행의
상세가 동시에 열릴 수 있다는 의미이며 거래 확인 dialog로 재사용하지 않는다.
