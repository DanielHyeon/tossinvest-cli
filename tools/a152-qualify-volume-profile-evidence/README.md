# Offline volume-profile evidence qualifier

This local tool classifies caller-supplied evidence. It neither collects data nor computes LVN/HVN, changes trading behavior or authenticates source, coverage, license or calendar. Synthetic data can be structurally eligible but cannot qualify as empirical VP input. Profitability remains inconclusive. A missing or unsupported profile does not block other research.

Run `python3 tools/a152-qualify-volume-profile-evidence/analysis.py INPUT.json [--output NEW.json]`. Test with `python3 -m unittest discover -s tools/a152-qualify-volume-profile-evidence -p 'test_*.py'`; the repository gate does not collect this suite. Output is JSON on stdout or an exclusively created file; existing paths and symlink traversal are refused. Input bytes are never modified. Output reports their SHA-256; exclusive creation is not a crash-durability guarantee.

Envelope: `version` = `a152-v1`, `synthetic` boolean, `datasets` array. Each dataset contains exactly `id`, `kind`, `market`, `symbol`, `currency`, `basis`, `profile_mode`, `session`, `cutoff_at`, `as_of`, `source`, `coverage`, `correction_policy`, `price_increment`, `records`, `bin_method`, `access`. See `testdata/synthetic.json` for complete examples. Values are caller assertions, including event IDs, coverage, source, calendar and access.

KR/KRW and US/USD with unadjusted prices are supported. The session object has `date`, `timezone`, `open_at`, `close_at` with explicit offsets and correct IANA zone/date. All timestamps use `YYYY-MM-DDTHH:MM:SS`, optional 1–6 fractional second digits, and `Z` or a whole-minute `±HH:MM` offset; excess precision and fractional offsets are rejected. The supplied session is not certified as an exchange session. `current_prefix` requires open < cutoff <= as_of <= close; `prior_session_fixed` requires cutoff = close and as_of on a later local date. The latter does not certify the immediately preceding exchange session. Coverage covers `[open, cutoff)` and must declare exact start/end, complete status and sequence, no gaps, venues and trade types. Its status is always unverified.

`source` contains `name`, `version`, `reference`, `declared_kind`; `coverage` contains `start_at`, `end_at`, `status`, `gaps`, `sequence_status`, `venues`, `trade_types`; `access` contains `license`, `availability`, `cost_note`. `price_increment` is a supplied zero-origin grid, not certified exchange tick rules. Correction policy must be `none_declared` for qualification; it does not prove corrections were absent. Corrections and cancellations are unsupported rather than replayed.

Trades contain `event_id`, `action`, `reference_id`, `executed_at`, `received_at`, `price`, `volume`. IDs must be unique, receipt times nondecreasing, executions inside `[open, cutoff)` and receipts no later than as_of. Bins contain `lower`, `upper`, `volume`; `bin_method` declares `name`, `volume_basis`, `unit`, `boundary`, `width`, `price_min`, `price_max`, `zero_bins_explicit`, `built_at`, `received_at`. Bins must be contiguous, include zero intervals, use executed shares and `[lower,upper)`; cutoff <= build <= receipt <= as_of. Bins do not reconstruct individual trades. OHLCV, orderbook and unavailable kinds use empty records and null method and are never converted into executed volume.

At most 16 MiB, 100 datasets, 100,000 total records, 512 characters per string and 64 per unsigned plain-decimal value are accepted. Unknown fields, duplicate JSON keys and duplicate dataset IDs are refused. Bad envelopes fail the CLI; bad datasets remain isolated as `invalid`. Other statuses are `eligible_unverified`, `unsupported`, `not_ready`. Every dataset supplies VP eligibility and exclusion reasons; no result grants production authority.
