# Offline initial-stop comparison

This tool compares fixed 0.7%, confirmed signal-bar low minus one tick, and 1.5×ATR14 stops using the same simulated entry, target, costs and caps. It reads one local JSON manifest and prints JSON; `--output PATH` creates a new file exclusively. It never obtains market data, submits orders, changes settings or modifies its input. Values, sources, calendar and tick information are caller-supplied and unverified. Synthetic calculations test arithmetic only; profitability is always inconclusive. EMA and FX are unsupported.

Run `python3 tools/a151-compare-stop-policies-offline/analysis.py input.json [--output new.json]`. Run tests with `python3 -m unittest discover -s tools/a151-compare-stop-policies-offline -p 'test_*.py'`; the repository aggregate gate does not discover this directory automatically.

The top-level JSON object has exactly `version` (`a151-v1`), `synthetic` (boolean), `mode` (`initial_stops`) and `candidates` (at most 1000). Every candidate has exactly:

- `id`, `market` (`KR` or `US`), `currency` and `account_currency` (both `KRW` for KR, `USD` for US), `symbol`, local `date` (`YYYY-MM-DD`), `basis` (`unadjusted`), `data_source`, `data_version`, `signal_confirmed_at`, `signal_close_at`.
- `session`: `source`, `version`, `digest`, `as_of`, `timezone`, `kind` (`regular`, `early_close`, `holiday`), `open_at`, `close_at`. All timestamps carry explicit UTC offsets. Timezone is `Asia/Seoul` or `America/New_York` for its market. A holiday yields no trade.
- `tick`: `source`, `version`, `digest`, `as_of`, `market`, `symbol`, `valid_from`, `valid_until`, `value`, `min_price`, `max_price`. One bounded, zero-origin grid applies to the whole session; no exchange rules are inferred.
- `cost`: `source`, `version`, `digest`, `as_of`, `currency`, `buy_rate`, `sell_rate`, `tax_rate`, `buy_fixed`, `sell_fixed`, `quantum`.
- `limits`: `source`, `version`, `digest`, `as_of`, `currency`, `risk_budget`, `max_quantity`, `max_notional`.
- `entry_slippage_ticks`, `exit_slippage_ticks`: nonnegative JSON integers. `bars_1m`, `bars_5m`: ordered arrays of objects with `close_at`, `received_at`, `open`, `high`, `low`, `close`, `volume`.

Prices, quantities, rates and other numeric values are unsigned plain decimal strings of at most 64 characters. Bars use close-time labels and must be aligned; received times must not precede closes. The first 5-minute close anchors 14 true ranges; signal-time inputs and snapshots must already be available. A supplied five-minute bar whose five constituent one-minute bars are present must match their aggregate. A missing constituent before confirmation excludes the candidate; missing constituents afterward are explicitly marked unverified while the one-minute execution path is censored at its first gap. The first scheduled minute open strictly after confirmation is the simulated entry; its later complete bar is outcome evidence, not a contemporaneous order. Missing next open is unfilled; later missing bars or an open position at session close are censored.

Results include the input SHA-256, model snapshots, entry/stop/target/quantity, initial risk, fees and tax, simulated net PnL and R, and per-market paired counts. Non-terminating exact rationals are `numerator/denominator`; monetary values stay in the market's quote currency. Censored mark PnL is gross and is never a simulated exit. Stop-first is the base result when a bar touches both levels; arm-specific target-first sensitivity is not a jointly achievable paired bound. A post-entry invalid exit remains attached to its affected arm and does not erase the eligible candidate or other arm outcomes. Complete paired means use only candidate IDs closed in all three arms; no denominator yields `null`. Calendar/tick claims and sample profitability are not independently verified.
